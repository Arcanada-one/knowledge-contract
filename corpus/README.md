# Public corpus allowlist

This file is the allowlist of documents that an indexer may read from this repository. As of the commit that introduced this wording the table below has **no rows**; read the table, not this sentence, for the current state. The unpublished research package is excluded.

An indexer may read only a path listed in the table with a merged source commit, a content digest, a publication decision, a license and a status. An absent or incomplete row means **deny**, including for files that are public in this repository. A pull request, an unmerged commit, or a file under `papers/`, `spec/`, `articles/` or `schemas/` that has no row is not an allowlist entry. Only Markdown files under those four directories can be listed. A secret-shaped or oversized file is quarantined by the exporter.

## How a row becomes eligible (DEC-AUP-0171)

The old route asked a second GitHub identity for an approving review. All work here is authored by one service account and the operator signs nothing, so it is replaced, not weakened, by a decision file with a receipt. The exporter (`tools/export_corpus.py`) refuses a row unless every check below passes on the pinned `main`:

1. **Decision file.** `corpus/publication-decisions/<batch>.jsonl` holds one canonical JSON line per decision (sorted keys, no spaces) with exactly the keys `schema` (`KnowledgeContractPublicationDecision/v2`), `path`, `sha256`, `rights_holder` (a named person), `license`, `status` (`current`, `superseded` or `withdrawn`), `upstream`, `rights_basis`, `third_party`, `attribution`, `limits` and `receipt`. `rights_holder` must be a named person (at least two capitalised words, not a group or a placeholder); `rights_basis` must quote the holder string that `REUSE.toml` assigns to the path at the row's source commit and must mention DCO as a word (the exporter checks only that `DCO` appears as a whole word, so `DCOM` and `noDCO` do not count; that contributor parts rest on DCO sign-offs that are declared, not verified is covered by the reviewer checklist, not by code), and `rights_basis` and `limits` must be non-empty; the rights holder must equal the name before the first comma on an `Author:` line of `NOTICE` at the source commit (any of several such lines); `upstream` is `original` or `<owner>/<repo>@<40 hex commit>:<path>` (the repository name is compared case-insensitively with this repository, and a `.git` suffix or any other alias is refused); `receipt` must be the receipt of the line's own batch (`receipts/<batch>.json` for `<batch>.jsonl`) and that file must exist, also for a line without a row. An exact repeat of a whole line is refused. Among lines with the same path, digest, rights holder, license and status the last one counts (ordered by the position of the introducing commit in main's first-parent history, then file name, then line order), so a key can return to `current` through a new line with its own receipt. The effective status of a path and digest is that of its last line of any status. A row must equal the last line of its key (path and digest) on path, digest, rights holder, license and status; a row that matches only an earlier line refuses. For a non-current row the `Publication decision` cell points at the last `current` line before the status line. A decision without a row exports nothing, but every decision line must have been introduced by a merged pull request that passes the checks below; otherwise the export refuses.
2. **Write-once tree with a fixed layout.** The `corpus/publication-decisions/` tree may hold only `<batch>.jsonl`, `receipts/<batch>.json` and `receipts/<batch>/reviewer-<n>.md` and `.input.txt`, where a batch name uses only letters, digits, `_` and `-` (no dots, no subdirectories, no other file); any other file there refuses the export. Every file in the tree (decision files, receipts, reviewer inputs and transcripts), whether or not a receipt names it, gets the secret scan and the deny scan; the deny scan is case-insensitive and covers `/home/`, `/Users/`, `/run/user/`, `arcana-*` host names, `*.ts.net`, and the addresses 10/8, 172.16/12, 192.168/16, 100.64/10, 127/8, 169.254/16 and IPv6 unique-local fc00::/7. The tree is write-once per file: a file is created in one commit and never modified, renamed or deleted, and new decisions go in new batch files. The exporter refuses if any first-parent commit of `main` changed an existing file there, and it refuses a decision merge commit in which any decision-tree file that differs from the first parent is not byte-identical to its version in the second parent (no evil merge).
3. **Receipt.** `corpus/publication-decisions/receipts/<batch>.json` names the reviewed head, the base, the digest of the reviewed diff, the digests of the decision lines the change adds (the set must equal the lines the change really adds); there are no other keys, and at least two blind reviewers, all `APPROVE`, with distinct session ids and distinct transcripts. The digest is the sha256 of the bytes of `git diff --no-renames --no-ext-diff --binary --full-index -U3 <base> <reviewed head>` (run with `diff.algorithm=myers` and `core.autocrlf=false`) followed by the line `--files--` and the sorted changed file names, one per line. The base is the unique merge base of the reviewed head and the decision change's first parent, and the reviewed diff touches only decision files. Each reviewer's input (`receipts/<batch>/reviewer-<n>.input.txt`) is exactly: the diff bytes, then `--sources--` and, for each decision line sorted by path, a line `BLOB <path> <sha256> <upstream> <length>` followed by the blob bytes read at the base and a newline (the exporter recomputes each digest), then `--declarations--` and, for each distinct upstream sorted, an `UPSTREAM <upstream>` line followed by `DECL <name> <length>` records with the bytes of `REUSE.toml`, `NOTICE` and `LICENSE`: for original text at the row's source commit, for an upstream in this repository at that upstream commit (which must exist), both recomputed from git; for an upstream in another repository, such as the site's `llms.txt`, at least one non-empty `DECL` record whose bytes are recorded and cannot be recomputed. Then `--checklist--` and the checklist text whose digest is pinned in the exporter. The transcript `reviewer-<n>.md` embeds the reviewer's session id and input digest, may begin with a line `SCRUBBED: <n> replacements`, and ends with the exact line `VERDICT: APPROVE <diff digest>`. The receipt, inputs and transcripts must be introduced by commits after the reviewed head and inside the decision pull request, and must be byte-identical on `main`. They are scanned for secrets and for host paths (`/home/`, `/Users/`, `/run/user/`), IPv4 addresses 10/8, 172.16/12, 192.168/16, 100.64/10, 127/8 and 169.254/16, IPv6 unique-local addresses (fc00::/7) and internal host names (`arcana-*`, `*.ts.net`), matched case-insensitively, before they are committed and again by the exporter, because this repository is public; public domains and public addresses are not denied.
4. **Order.** Content first, then the decision, then the row, each in a merged pull request of its own. The source commit is a first-parent commit of `main` and an ancestor of the receipt's base. The pull requests found for the decision and row commits must target `main`. A decision pull request is merged with a merge commit, whose second parent equals the pull request's final head as the GitHub API reports it, so that every reviewed commit is in history; a squash or rebase merge is refused. The decision change touches only decision files. The row change, taken as the first-parent commit that most recently added the row text, may touch only `corpus/README.md`, and only by adding or removing table rows; a status line's decision change must precede it. A decision merged in the same pull request as its content or its row is void: CI fails a pull request that changes two of decision-tree files, `corpus/README.md` and content paths, and the exporter refuses the export if they were mixed anyway. The row is found by the raw text of its table line, not by a successful parse, and the export refuses if any version of the table after the decision fails to parse.
5. **Fields.** A row matches a decision by exact equality of path, digest, rights holder, license and status. The row license must equal the license that `REUSE.toml` at the source commit assigns to the path (more than one matching override refuses), and must be `CC-BY-4.0` or `Apache-2.0`.
6. **Scope.** Until a later DEC changes the `SCOPE_PATHS` constant in the exporter, only these may be listed: the six already-public documents mirrored under `articles/` (DEC-AUP-0171) and the 14 English entry pages of the Meaning Management papers listed in the constant, each named in full (DEC-AUP-0172). The Russian full texts under `papers/ru/`, `papers/README.md` and everything under `spec/` are not in scope; a row for any other path refuses. Being in scope lets a row be written; it is not a row, and the table above lists no paper until its own decision and row pull requests are merged.
7. **Status.** Every row's status, including `current`, must equal the effective status of its path and digest, so a later `withdrawn` or `superseded` line makes a still-current row refuse.

What this proves and what it does not. The records (receipt, reviewer inputs, transcripts) are written by the same account that writes the content, under the same model family, and the writer chooses what the reviewers see. The exporter checks that the records are consistent with git (digests, ordering, retained bytes, ancestry) and with the files they describe; it cannot check that they are authentic, and the writer can fabricate the record. The manifest labels this as `reviewer_identity_class` `same_account_blind_agent`. It does not show independence, the identity of the author, copyright of agent-written text, or the absence of unrecognised third-party material. A generic code approval of a pull request does not establish publication rights.

## Corrections and withdrawals

A correction appends a new row for the new revision whose `Supersedes` cell names the old digest, and a later `superseded` decision line for the old digest. A withdrawal is a later `withdrawn` line and a row marked `withdrawn`; it has no replacement row. A non-current row never exports content but keeps its provenance. Rationale text may be kept under `corpus/decisions/`. A current row uses `none` for `Status decision`.

## Table cells

The `Publication decision` cell points at the matched `current` line as `corpus/publication-decisions/<batch>.jsonl@<commit that introduced it>#<sha256 of the canonical line>`. The `Status decision` cell has the same form for the `superseded` or `withdrawn` line of a non-current row and is `none` for a current row. Documents mirrored from other public sources, such as the project's own site, are listed only after the same route and never contain text the author has not published under the stated license.

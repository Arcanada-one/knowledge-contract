# Machine-readable schemas

The current publication catalogue is validated by [tools/check_publication.py](../tools/check_publication.py). The canonical architecture is defined in [engineering/specifications](../engineering/specifications/README.md).

The [book-package schema](book-package.schema.json) implements `book-package/2` with `KCBook*/v2` record tags, with [synthetic fixtures](fixtures/book-package/), a [cross-file validator](../tools/check_book_package.py) and [conformance tests](../tools/test_book_package.py). Its complete [specification](../engineering/specifications/book-package/SPECIFICATION.md) separates structural checks from unmeasured conversion fidelity and runtime admission.

The [observation and change-event schema](contract-observation.schema.json) implements the bounded `kc-observation/1`, `kc-dependency-change/1` and `kc-profile-advertisement/1` profiles. [Exact synthetic examples](fixtures/contract-observation/valid/), the [validator](../tools/check_contract_profile.py) and [regression tests](../tools/test_contract_profile.py) cover shapes, strict JSON parsing, byte identity, scoped observations and epoch rules. A serialized in-memory publication model exercises the specified atomic guard without claiming a distributed service.

The [document classification schema](document-classification.schema.json) implements `DocumentClassification/v1` for the `kc-doc-class/1` canon of the repository-only [pipeline specification](../engineering/specifications/pipeline/SPECIFICATION.md), with [synthetic fixtures](fixtures/document-classification/) and a [checker](../tools/check_document_classification.py).

The [location registry schema](location-registry.schema.json) implements `LocationRegistry/v1`, `LocationRegistryRow/v1` and `LocationVerifyReceipt/v1` for the repository-only [location-registry specification](../engineering/specifications/location-registry/SPECIFICATION.md), with a [checker](../tools/check_location_registry.py) and [finite tests](../tools/test_location_registry.py). It does not claim a populated live store or KC2 admission.

The [package index card schema](package-index-card.schema.json) implements `PackageIndexCard/v1` and `PackageIngestReceipt/v1` for the repository-only [package-index-ingest specification](../engineering/specifications/package-index-ingest/SPECIFICATION.md), with a [checker](../tools/check_package_index_card.py) and [finite tests](../tools/test_package_index_card.py). Cards carry source/package ids, span and licence/publication state; live Scrutator search, S3 resolve and edge query stay `not_measured` until measured.

The [KC admission observation schema](kc-admission-observation.schema.json) is a CANDIDATE `KCAdmissionObservation/v1` (KCLIVE-01): a closed, discriminated record (`observed` with a native source, an exact-byte digest and one resolver outcome, or `unavailable` with a typed reason) of a resolver outcome that a native service already persisted. Its claims scope is fixed to `resolver-outcome-observation-only` and issuer authority, source admission, runtime authorization, consumer delivery and publication are all `NOT_MEASURED`; schema validity never means admission. The eight formerly provisional choices are resolved by KC-Brain 6711021786 (`message_id` is removed; the reasons `native_record_invalid`, `native_binding_unverified` and `unsupported_source_shape` are added; an `unavailable.subject` is the requested target only). The [checker](../tools/check_kc_admission_observation.py) has three explicit modes: `structure-only` reports structural validity alone and says so; `strict-evidence` requires the exact native bytes of an admissible source and compares every emitted fact (task, outcome, verdict, time, schema, contract halves, obligations, missing, refusal code) with a supported native source profile, and without the bytes it is a typed refusal, never a pass; `diagnostic-agreement` compares the same facts with mutable bytes, but its result has its own level (`diagnostic-content-agreement`), the flag `KCAO-FLAG-NON-ADMISSIVE` and exit code 5, and is never strict evidence. KC-Brain 6711755408 (choice b): a digest-named mutable `ArganaContractRecord/v1` is not an admissible strict-evidence source, since a matching hash is content agreement only; strict-evidence never passes it (explicit mutable bytes are refused with `KCAO-SOURCE-MUTABLE`, an implementer-chosen name pending KC-Brain review; no retained event source is the typed `unavailable` / `exact_bytes_unrecoverable`, exit 3), and a future `ArganaIntakeSnapshot/v1` (Argana PR65 candidate) is not registered, so such a source is `KCAO-NATIVE-PROFILE` (`unsupported_source_shape`). Source time (provisional fail-closed reading of 6711021786 choice 1 after Agent-Brain 6711758550; KC-Brain may instead permit omission as a narrower projection): `native_source.recorded_at` is the producer time copied exactly from the supported source (`stored_at_utc`), never the observer receipt time; a known source time that the observation omits is refused with `KCAO-NATIVE-MISMATCH`, and a source without a time leaves `recorded_at` absent (accepted). Synthetic labels and the synthetic work-item binding are valid only with `--fixture` and then pass at the level `fixture-evidence`, never as a native observation. Fixture mode applies to synthetic sources only (Agent-Brain 6712290533 R-KCAO-FIXTURE1): `--fixture` is accepted for the synthetic source system and synthetic identities alone, a real source system with `--fixture` is refused in every mode with `KCAO-FIXTURE-NOT-SYNTHETIC` (an implementer-chosen name), and the mutable-source refusal of `strict-evidence` is unconditional, so a real-labelled input is never `fixture-evidence` and never exit 0. The native Argana digest-named `ArganaContractRecord/v1` can support only the `contract` branch, and it is mutable metadata, so it cannot be an immutable intake event (KC-Brain D): until native capture exists the honest live result is `unavailable`, no work-item binding profile is approved (the live record omits `work_item_id`, and a consumer that requires the binding gets `unavailable` / `native_binding_unverified`), and underdetermined/refusal have no durable native source. [Synthetic fixtures](fixtures/kc-admission-observation/), the checker and [tests](../tools/test_kc_admission_observation.py) cover the cross-field rules.

The [requirement register](../engineering/specifications/requirements.json) lists stable normative identifiers and distinguishes available finite regression examples from implementation-specific evidence still required.

This directory does not claim to contain a stable universal Knowledge Contract wire schema. Historical bounded profiles retain their identifiers and measured scope in the [compatibility record](../appendices/source-map/APPENDIX.md#4-protocol-compatibility). A newly published schema must state its exact profile, interpretation, migration rules and conformance evidence; an editorial edition number is not a wire-format release.

## 1. What this roadmap covers

This is the complete reading map of the agreed publication and research programme, not a claim that every future question has been anticipated. It covers the English corpus, readable naming, Russian and Simplified Chinese editions, primary-source assessment, foundations, evidence recovery and practical validation. Muneral remains the execution authority; these files define outputs and acceptance criteria, not a second task system.

The catalogue contains 30 edition-1.1 works: nine papers, eleven specifications, six studies, a glossary, a bibliography and two appendices. Meaning Bridge remains a research draft. Source publication, semantic acceptance, a site deployment and backend index admission are separate observations.

**9 November publication direction:** Pavel instructed KC-Brain to finish the initial public-reading state, use understandable names and proceed with the prepared production release through normal review and checks. That instruction supersedes the earlier blanket pause for this bounded publication lane. It does not dispatch unrelated costly experiments, grant native authority or assert that a new deployment has already happened.

## 2. A finite release and an open research programme

A release is a finite selected set of exact documents and explicit limitations. Research can continue indefinitely without keeping that release permanently unfinished. The accepted English baseline is distinct from proposed scientific revisions and runtime implementation. A title-only correction changes bytes but does not automatically change an argument or transfer an earlier exact-version review.

The foundations programme proceeds through Meaning Bridge, Semantic Bridge, Transformation Algebra, Semantic Geometry, Semantic Verification and Meaning Controls. The existing [foundations plan](roadmap/FOUNDATIONS_RELEASE_PLAN.md) retains its detailed acceptance obligations. This future package is not a retroactive gate on authorized corrections, an accepted English edition, reviewed translations or the initial reading release. The baseline exact-consumer pilot does not inherit advanced geometry prerequisites. A new costly run still needs its own authorization and prepared protocol.

## 5. Practical validation and its separate evidence

| Capability | Content or boundary to establish | Evidence required for an execution claim |
| --- | --- | --- |
| Observable agent runs | Exact subject, attempted operation and observations | Real retained runs and useful positive controls, not just screenshots or schemas |
| Faithful export | Meaning-bearing fields, qualifiers and media | Checks of actual converter/renderer output, including omissions and unsafe structure |
| Source addressing | Source, object and representation identity | Exact-source and locator readback, not a title or retrieval hit |
| Durable reading evidence | Complete retained bytes and append/write behavior | Corruption, malformed JSON, symlink, incomplete-write and crash-boundary controls |
| Required context | Preserve obligations; distinguish discharge and authority | Checks at actual model/tool dispatch, not execution from an obligation string |
| Safe routing | Supported profiles and permitted consumers | Unsupported-reader and wrong-recipient controls on actual routes |
| Recovery | Continuation after interruption | Retained history and no duplicate external effect |
| Resource boundaries | Complete budgets and stopping behavior | Measured limits, useful completion and explicit exhausted-budget outcomes |
| Joint readiness | Compatible source, reader, implementation and policy | A coherent end-to-end snapshot rather than unrelated green checks |
| Storage integrity | Distinct file/package/registry and authority identities | Authenticated storage readback; fixtures remain synthetic |
| Cross-package relations | Typed endpoints and trusted mandatory requirements | Missing, changed, withdrawn and conflicting-relation controls |
| Source influence | Controlled source-change comparison | Observed intended outcome changes; retrieval alone is not evidence of use |

These streams refine the existing research graph, not a second tracker. [Knowledge Checks](reference/document-naming/CHECKS.md#knowledge-checks-mandatory-requirements-and-evidence-assessment) and [Execution Checks](reference/document-naming/CHECKS.md#execution-checks-authorization-budget-and-result-integrity) provide readable scenario names without turning prepared tests into observed native results. Broader runtime research does not automatically block static scientific publication.

## 6. Repository completion and later website handoff

Repository readiness means readable catalogue titles and document entry points, stable paths, a complete named roadmap, explicit translation coverage and checks with truthful subjects. It does not mean all planned research is finished. The [first translation batch](translations/release/README.md) provides exact source and target inputs and the existing review evidence; it is not yet a served-publication receipt.

The site handoff uses an accepted immutable source SHA. It updates cards, navigation, page titles, alternate-language labels, download links, search labels and roadmap entry links coherently. Compare actual served bodies, formulas, tables and source pins on mobile and desktop. Old labels remain searchable aliases of the same work; IDs and historical URLs stay valid. Reindexing a backend requires the separate admitted index procedure and actual readback.

The [handoff specification](roadmap/SITE_DELIVERY.md) remains the technical checklist, interpreted under Pavel's new bounded publication instruction rather than its older blanket-pause wording. Content changes, current-source mapping, rendition decisions, ordinary merge, site deployment and index promotion retain their separate checks. Future translations or unrelated native-authority work are not invented prerequisites for the ready English reading release.

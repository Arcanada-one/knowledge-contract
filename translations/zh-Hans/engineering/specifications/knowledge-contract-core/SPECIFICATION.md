# 知识契约：核心模型与准入要求 {#knowledge-contract-core-model-and-admission-requirements}

**作者：**Pavel Valentov · **出版版本：**1.1

## 1. 目的与符合性 {#1-purpose-and-conformance}

本文是一组架构要求。互操作性需要具名的表示配置；已实现的交换子集仅限于[观察、变更事件和配置通告](../status-model/SPECIFICATION.md#8-bounded-exchange-profile)，而[书籍包配置](../book-package/SPECIFICATION.md)具有自己的模式。这并不意味着已有完整契约的传输格式或已部署的运行时。

知识契约将一组知识绑定到其预期用途、依据、依赖、约束和评估。它让接收者能够检查所提供的内容、哪些条件重要，以及实际检查了什么。它不会将来源断言变成事实，也不会将指令变成行动许可。

本规范定义符合要求的实现应具有的架构。大写的要求用语遵循 [BCP 14](../../../../../reference/bibliography/BIBLIOGRAPHY.md#requirement-language)。

**KCC-R001.** 符合性声明必须（MUST）指明所实现的配置、配置版本、读取器和接受评估的范围。

完整符合性声明不能仅凭模式检查成立。出版版本 1.1 是本文档的版本；序列化配置保留各自的版本。[兼容性记录](../../../../../appendices/source-map/APPENDIX.md#4-protocol-compatibility)标识现有的有限实现，而不为其重新命名。

## 2. 核心模型 {#2-core-model}

契约具有九个逻辑分组。

**KCC-R002.** 如果映射保留各组的义务，序列化器可以（MAY）采用不同的组织方式。

| 分组 | 必需含义 |
| --- | --- |
| 身份 | 稳定的对象身份、不可变修订版、契约定义和表示配置的版本 |
| 目的 | 预期用途、任务和要求修订版、接收者、必需配置 |
| 内容 | 可寻址单元、其语义角色、来源引用和受保护条件 |
| 范围 | 适用条件，以及明确的未知、不适用或不予披露值 |
| 依据 | 支持每项相关断言的来源修订版、定位符、推导和证据 |
| 依赖 | 将必需关系与可选阅读链接加以区分 |
| 义务 | 前置条件、不变量、保留义务、覆盖要求和验收义务 |
| 投影 | 已交付的表示、纳入和省略的单元、声明的损失与变换 |
| 观察 | 绑定对象修订版、方法、观察者、时间和限制的评估 |

**KCC-R003.** 空列表必须（MUST）表示在声明范围内已经确立的空集合。

**KCC-R004.** 空列表不得（MUST NOT）代替未知集合。

**KCC-R005.** 配置可以（MAY）将确实无关的分组表示为不适用，并说明理由。

**KCC-R006.** 配置不得（MUST NOT）因没有可用证据而默默省略必需义务。

契约的不可变内容与当前使用它的决定是两种记录。撤销具体授权会改变某项用途的可接受性，但不会重写早期契约的内容。

## 3. 约束是一等义务 {#3-constraints-are-first-class-obligations}

**约束**限制可接受的解释、变换、交付或行动。

**KCC-R007.** 每项约束必须（MUST）具有身份、对象、范围、谓词或可读规则、相关时的权限来源、严重程度，以及检查方法或明确的未决状态。

**KCC-R008.** 实现必须（MUST）保留该约束的适用条件和依赖。

[制品登记规范](../artifact-registry/SPECIFICATION.md#4-constraints-and-professional-artifacts)定义可读的 `CONSTRAINT.md` 制品。

必须区分以下四类：

| 类别 | 问题 | 抽象规则示例 |
| --- | --- | --- |
| 适用条件 | 知识在什么情境下适用？ | 输入属于声明的定义域 |
| 行动约束 | 哪些行为被禁止或受到限制？ | 操作只能写入指定资源 |
| 执行者能力要求 | 此执行者能否执行所需方法？ | 某项评估覆盖该技能和环境 |
| 验收标准 | 什么能够表明请求结果已实现？ | 交付的输出满足固定版本的标准 |

**KCC-R009.** 一项约束也可以是验收义务，但两者关系必须（MUST）明确。

满足输出标准不能为获得结果时采用的禁止行为开脱。技能描述不能确立执行者能力。角色指派本身不会提供具体授权。

**KCC-R010.** 组合配置时，所有适用的强制约束必须（MUST）继续生效，除非已识别的权限主体在与证据相同的声明信任边界上通过认证，并在其经过验证的权限范围内明确解决了冲突。

**KCC-R011.** 加载顺序、后面的段落或更方便的结果不得（MUST NOT）隐式覆盖限制。

矛盾应阻止受影响的用途，或产生范围更窄且明确获准的替代方案。

## 4. 配置与兼容性 {#4-profiles-and-compatibility}

支持的配置族包括专业工作、对话、文档、推理、视觉表示和复用。每个配置声明其版本、存在原因、是否必需以及载荷。配置的必要性来自声明的目的和要求；不能假设解析器能从任意自然语言中正确推断这种必要性。

**KCC-R012.** 读取器必须（MUST）通告其支持的表示和必需扩展。

未知的必需配置使契约不能用于该请求。承载任何强制约束的配置均为必需配置，不受生产者提供的“可选”标志影响。

**KCC-R013.** 读取器必须（MUST）结合可信请求或政策、已知约束引用以及配置声明来推导必需性，并且必须（MUST）阻止未知的约束承载配置。

如果无法确立某个不透明配置与约束的相关性，则在准入时它应视为未知，而非无害。

**KCC-R014.** 只有已经确立与每项强制义务均无关的扩展，才可以（MAY）作为可选的不透明数据保留，并报告这一限制。

保留其字节不等于验证其语义。兼容性是有方向的：新读取器能够接受旧记录，并不能证明旧读取器能够安全地重写新记录。

## 5. 准入与执行 {#5-admission-and-execution}

**KCC-R015.** 准入必须（MUST）评估精确的契约修订版、要求、接收者、环境、适用约束、强制依赖和当前权限。

每项强制检查产生通过、失败、未知或有依据的不适用结果。

**KCC-R016.** 未知不得（MUST NOT）被提升为通过。

执行还需绑定工作项修订版、要求修订版、契约修订版或摘要、尝试、执行者、相关的具体授权和能力、输出身份，以及针对各项标准的证据。接收计划不等于执行。进程成功退出不等于验收。如果超时后远程效果仍不确定，该尝试在核对之前保持未决；重试需要明确的重复策略。

**KCC-R017.** 符合规范的执行适配器必须（MUST）在其声明的信任边界上验证证据来源。

由不可信调用者提供一个声称证据可信的布尔值，并不足够。现有有限模型将所提供的上下文作为前提，并不提供上述生产环境信任边界；相关研究已测量并揭示这一限制。

## 6. 迁移与失败处理 {#6-migration-and-failure-handling}

迁移创建新的表示，并保留来源修订版和变换记录。缺失的条件、具体授权或能力仍然是未知的。自由文本形式的方案蓝图不会自动转换成流程图。

**KCC-R018.** 必须（MUST）报告未映射字段和语义损失。

仅有模式有效性不能证明 `semantic_equivalence`。

**KCC-R019.** 拒绝报告应该（SHOULD）指明未满足的义务以及可据以采取行动的原因，同时不得向未经授权的接收者披露受保护的依据。

**KCC-R020.** 当组装、授权或证据检查失败时，实现不得（MUST NOT）创建看起来成功的输出。

## 7. 验收用例与证据 {#7-acceptance-cases-and-evidence}

**KCC-R021.** 符合性测试集必须（MUST）包括：受支持的正向请求；缺失的必需依赖；未知的必需配置；冲突约束；过时的要求修订版；未经授权的执行者；不匹配的输出证据；带有未知值的迁移；以及虚假的可信证据声明。

**KCC-R022.** 模式、内部一致性、适用性和执行验收必须（MUST）分别报告。

[契约配置研究](../../../../../engineering/studies/contract-profile-conformance/STUDY.md)报告了 35/35 和 26/26 的有限场景结果，同时保留了错误可信输入被接受的情况，以及 9/9 对 9/9 的基线持平结果。这些观察支持有限的符合性声明，并暴露信任边界缺口；它们不确立一般任务优势或生产环境授权。

科学依据见[受控知识复用](../../../../../papers/controlled-knowledge-reuse/PAPER.md)、[证据与证伪](../../../../../papers/evidence-and-falsification/PAPER.md)和[共用术语表](../../../reference/glossary/GLOSSARY.md)。

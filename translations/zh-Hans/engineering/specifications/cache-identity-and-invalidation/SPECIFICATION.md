# 缓存身份、依赖跟踪与失效处理 {#cache-identity-dependency-tracking-and-invalidation}

**作者：**Pavel Valentov · **出版版本：**1.1

## 1. 目的与符合性 {#1-purpose-and-conformance}

本文是一组架构要求。互操作性需要具名的表示配置；已实现的交换子集仅限于[观察、变更事件和配置通告](../status-model/SPECIFICATION.md#8-bounded-exchange-profile)，而[书籍包配置](../book-package/SPECIFICATION.md)具有自己的模式。这并不意味着已有完整契约的传输格式或已部署的运行时。

本规范规定如何标识保存的结果、将其查找为候选项、在变化后使其失效，并在交付边界上准入。字节相等、配方相等、语义适合性和当前授权是不同关系。

大写要求用语遵循 [BCP 14](../../../reference/bibliography/BIBLIOGRAPHY.md#requirement-language)。该架构由条件论证和有限模型支持，而不是声称已经部署分布式一致性协议。

**CCH-R001.** 每个实现必须（MUST）说明其一致性假设和失败行为。

参见[受控复用](../../../papers/controlled-knowledge-reuse/PAPER.md)。

## 2. 身份层次 {#2-identity-layers}

| 身份 | 固定了什么 | 未确立什么 |
| --- | --- | --- |
| 内容身份 | 具名哈希域中的精确字节或规范结构化值 | 含义、作者身份、真实性或许可 |
| 构建身份 | 声明的输入、配方、参数和相关环境 | 实际执行或确定性输出 |
| 查找身份 | 对查询、接收者和政策而言的候选类别 | 每个检索候选项的使用资格 |
| 当前选定修订版 | 命名空间和代次内选定的修订版 | 对所有消费者永久适用 |

**CCH-R002.** 查找之后必须（MUST）进行请求与制品描述符比较，以及必需的准入检查。

否定、量词、接收者、目的和范围，不是可以忽略的相似查询变体。

**CCH-R003.** 将摘要相等用作身份依据时，必须（MUST）说明摘要碰撞假设，以及所选字节域或规范值域。

已实现的字节域登记在[状态交换配置](../status-model/SPECIFICATION.md#8-bounded-exchange-profile)中；未命名的规范化过程不受支持。

请求描述符固定下列字段。制品描述符记录保存制品在准备和评估时所针对的对应值。

| 描述符组件 | 比较规则 |
| --- | --- |
| 目的与接收者标识符 | 精确身份；别名需要独立确立的身份映射 |
| 要求和标准引用 | 精确不可变修订版与摘要，或对每项新增强制要求的蕴含关系进行独立检查 |
| 表示与必需配置引用 | 精确配置／版本支持，或明确且经过检查、附带损失记录的适配器 |
| 对象、范围、量词和受保护运算符 | 具名表示配置下的精确结构，或明确的有界保留论证；相似性不足够 |
| 约束与权限引用 | 完整的当前强制集合，不忽略任何承载约束的配置；重新检查当前具体授权 |
| 必需输出／交付形式和预算 | 实际交付形式满足请求的配置和实际资源界限 |
| 时间模式与依赖快照 | 请求的历史、当前或有界陈旧政策，以及完整的当前读集检查 |

**CCH-R004.** 描述符比较必须（MUST）对相关组件逐项返回 `pass`、`fail`、`unknown` 或有依据的 `not_applicable`。

缺失字段、未知配置语义或未证明的蕴含关系仍为未知。

**CCH-R005.** 算法不得（MUST NOT）仅因为查找键、文本嵌入或来源字节相同，就将两个请求视为等同。

描述符相等是初步关卡，不是当前权限授予。该架构不序列化完整描述符；完整的描述符传输映射仍是特定配置的义务。

## 3. 依赖跟踪 {#3-dependency-tracking}

**CCH-R006.** 读集必须（MUST）包含对所声称复用保证具有实质意义的每项声明依赖，包括来源修订版、必需选择器、配置、规则、请求要求、编译器行为和授权状态。

依赖类别决定影响规则。相同字节搬迁可保留内容身份，却改变可访问性；解释变化可使适用性失效，却不改变来源文件。

**CCH-R007.** 否定结果和穷尽性声明还必须（MUST）跟踪其全集或索引代次，以及完整性假设。

新增内容无需修改任何此前选定对象，也可能使“无匹配”或“全部匹配”失效。Top-k 检索不提供这一完整性前提。

**CCH-R008.** 未知影响必须（MUST）依据政策触发重新评估，或产生保守的未决结果。

**CCH-R009.** 不得（MUST NOT）仅因旧键仍匹配就推断变化无害。

## 4. 变更事件与排序 {#4-change-events-and-ordering}

变更事件标识受影响依赖、旧／新修订版或代次、事件身份、排序命名空间和影响类别。

**CCH-R010.** 代次是非负整数；相关变化必须（MUST）严格推进受影响依赖的代次，即使内容字节没有改变。

权限撤销会改变可接受性，却不一定改变内容。

[交换模式](../../../schemas/contract-observation.schema.json)中已实现的 `KCDependencyChange/v1` 记录提供 `event_id`、`namespace`、`sequence`、`dependency_id`、`old_epoch`、`new_epoch`、旧／新修订版引用、类别、影响、观察者和时间。

**CCH-R011.** `new_epoch` 必须（MUST）大于 `old_epoch`；`revoked` 事件必须（MUST）携带 `impact: blocked`。

空修订版引用表示不存在可寻址修订版，而不是已经确立内容相等。事件类别为 `revision_changed`、`revoked`、`availability_changed` 和 `unknown_change`。影响采用[状态模型](../status-model/SPECIFICATION.md#3-canonical-dimension-vocabularies)。

**CCH-R012.** 接收者必须（MUST）仅在完整事件字节相同时对相同事件标识符去重，检测该标识符被冲突复用的情况，并将声明排序命名空间中的序列缺失或乱序视为需要核对。

配置序列化这些事实，但不提供事件传输，也不认证事件已完整送达。错失事件不能推出变化无害。

**CCH-R013.** 如果可能丢失事件，则在重新确认受影响准入声明前，核对必须（MUST）将观察到的依赖状态与权威状态比较。

**CCH-R014.** 断开连接的系统可以（MAY）按明确有界政策交付，但在一致性协议无法确立即时全局撤销时，不得（MUST NOT）声称具备该保证。

## 5. 受守卫约束的发布与交付 {#5-guarded-publication-and-serving}

**当前指针命名空间**标识一个有序的当前指针决策流。其**代次**是非负计数器，每次当前指针变化——包括回滚——以及每次适用于该指针的撤销，都严格递增。

**CCH-R015.** 回滚、重启、恢复或计数器耗尽后，不得（MUST NOT）复用代次值。

**CCH-R016.** 无法安全恢复计数器的运行时必须（MUST）建立新的命名空间，并使旧读集失效。

交换子集将整数限制在 2^53−1；耗尽时采取封闭式失败，而不是回绕。

**CCH-R017.** 工作进程的读集必须（MUST）包含命名空间与代次、每项实质依赖的精确修订版和代次，以及相关权限和政策代次。

依赖集合的完整性是保证的明确前提，而不是由缓存键推断的事实。

**CCH-R018.** 发布必须（MUST）就以下谓词作出一次可线性化决定：当前命名空间和当前指针代次等于工作进程预期值；每项声明的实质依赖仍具有所观察的代次／修订版；当前权限和政策允许此精确输出／用途；所有必需构建检查仍被满足。

**CCH-R019.** 当前指针更新及代次递增必须（MUST）与该决定原子地发生。

先单独检查依赖，再仅对当前指针做比较并交换，并不足够：撤销可能发生在两者之间。

**CCH-R020.** 每次相关撤销必须（MUST）在声明决策边界内推进其权限／依赖代次和受影响的当前指针代次。

**CCH-R021.** 延迟完成的工作进程不得（MUST NOT）恢复旧指针、撤销已有撤销，或在中间发生变化后，仍依据看似未变的依赖发布。

**CCH-R022.** 缺少覆盖上述全部条件的原子边界的部署必须（MUST）采取封闭式失败，或者明确提供更弱的具名一致性配置；它不能声称具有此严格保证。

**CCH-R023.** 交付守卫必须（MUST）在实际交付一致性点验证精确输出、相关的当前依赖代次和当前权限。

构建时验证不会授权后续无守卫交付。只有当锁、事务或有依据的“验证并提交”协议的范围覆盖整个谓词时，它们才是有效机制。边界之外的远程效果仍保留各自的核对语义。

**CCH-R024.** 租约必须（MUST）定义范围、到期、撤销行为、时钟假设和网络分区行为。

严格撤销声明不能将无法观察的撤销视为无害，除非明确采纳的授权语义允许所声明的延迟。

[参考模型与回归测试](../../../tools/test_contract_profile.py)在一个内存锁内串行化该谓词的命名空间、代次、依赖代次和撤销部分。它们不评估输出特定的授权、语义有效性或构建检查。它们展示延迟发布者、当前指针令牌下的依赖变化、读取与发布之间的撤销、并发发布者、当前指针或依赖计数器耗尽，以及不复用代次的回滚。这些是有限本地检查，不是分布式部署或持久崩溃恢复的证据。

## 6. 存储、恢复与可观察性 {#6-storage-recovery-and-observability}

驻留状态和使用资格相互独立。逐出可移除有效副本；保留可保存无效副本。

**CCH-R025.** 恢复必须（MUST）验证内容身份，并重新构建当前使用资格决定，而不是将历史肯定判断恢复为当前事实。

**CCH-R026.** 日志应该（SHOULD）记录查找候选项、比较的描述符、依赖观察、准入决定、发布代次和实际交付结果。

**CCH-R027.** 日志记录必须（MUST）尊重接收者的信息披露权限。

强制审计保留与缓存驻留时间是两种政策。

## 7. 验收用例 {#7-acceptance-cases}

必需测试包括：查询文本相同但接收者改变；查找键匹配但来源改变；新对象使否定结果失效；通过核对发现丢失的失效事件；延迟构建试图覆盖更新指针；恰好在硬截止时间到期；以及预检查与交付之间发生撤销。

**CCH-R028.** 每项测试必须（MUST）标识模拟的或真实的一致性边界。

[复用研究](../../studies/reuse-admission-and-cost-controls/STUDY.md)报告可用证据及其部署限制。[RFC 9111](../../../reference/bibliography/BIBLIOGRAPHY.md#http-caching)是 HTTP 缓存语义的参考，而不是此处定义的语义检查或权限检查已实现的证明。现有有限配置和保留结果见[兼容性附录](../../../appendices/source-map/APPENDIX.md#4-protocol-compatibility)。

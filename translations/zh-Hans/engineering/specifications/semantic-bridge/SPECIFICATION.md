# 语义桥接：从来源解读到可检查的操作 {#semantic-bridge-from-source-readings-to-checkable-operations}

**作者：**Pavel Valentov · **出版版本：**1.1

## 1. 目的与符合性 {#1-purpose-and-conformance}

语义桥接将实际检查过的来源材料、明确标注归属的解读、形式表示和指定计算联系起来。本规范针对[《语义类型》](../semantic-types/SPECIFICATION.md)中的区别，提供一种有界转换过程。其科学基础是[《意义桥梁》](../../../../../papers/human-meaning-and-computable-knowledge/PAPER.md)，特别是来源身份、解释依据与覆盖之间的分离。语义对象模型仍由[《意义与语境》](../../../../../papers/semantic-objects-and-context/PAPER.md)定义；本文既不引入与之竞争的意义理论，也不引入通用自然语言解释器。

可执行配置 `kc-semantic-bridge/1` 读取给定的纯文本来源和给定的解释包。它检查精确的来源绑定，解析一种有限的布尔规则语言，并在给定观察下计算每项保留解读的可能取值。在该语言范围内，它保留例外和备选解读。输出回答的是关于这些表示的条件性问题。它不证明解读忠实表达了周围文字、归属标注真实、给定观察为真，或某项行动已获授权。

**SBR-R001.** 符合性声明必须（MUST）标明本配置、其实现的不可变修订版以及实际执行的检查，不得将结果提升为对《语义类型》或知识契约的完整符合性。

大写要求用语遵循 [BCP 14](../../../../../reference/bibliography/BIBLIOGRAPHY.md#requirement-language)。既有要求保留其标识符。本配置细化 SEM-R002、SEM-R006–SEM-R011、KOP-R001–KOP-R010 和 STA-R001–STA-R004，而不替代这些要求。

## 2. 操作边界与责任 {#2-operation-boundary-and-responsibilities}

本地操作是**分析给定的备选规则**。其输入域由有限的来源字节串和满足第3–5节的包构成。输出要么是对所声明解释集合的完整求值，要么是明确的无效或不支持诊断。生成候选项、调查事实、鉴别来源真伪以及行动准入，均属于其他操作。

| 边界 | 本操作负责的事项 | 委托给其他操作或未予评估的事项 |
| --- | --- | --- |
| 从来源到选定单元 | 核对精确的来源字节、完整规则选择器和受控规则单元的完整清单 | 给定来源是否为所需的现实文档，以及是否包含全部必要上下文 |
| 从单元到解读 | 保留给定身份、归属标签和备选状态 | 谁实际创作或认可了内容；合理自然语言解读是否完整 |
| 从解读到形式对象 | 解析完整受控表达式，保留算子作用域，绑定每个局部原子 | 给定形式化和指称对象描述是否忠实解释了普通文字 |
| 从观察到可能世界 | 保留已知、未知和不予披露状态；使共享观察身份保持关联 | 给定值是否经过独立测量、是否具备时效性，以及是否真实可信 |
| 从形式对象到结果 | 在每个允许的布尔世界中对每项保留解读求值 | 对外部任务的适用性、执行者能力、当前权限，以及交付或执行是否成功 |

来源哈希是对给定字节的完整性绑定，而不是真实性证书。归属标注是给定的有关作者身份或话语角色的声明。调用方提供的任何值都不能仅凭出现在有效包中，就使这两类性质中的任何一种获得独立验证。

**SBR-R002.** 操作必须（MUST）按 KOP-R015 和 STA-R003 的要求，保留已检查结构与给定语义或事实假设之间的区别。

[参考实现](../../../../../tools/semantic_bridge.py)提供 `read_packet(path)`、`compile_rule(expression)`、`evaluate_ast(ast, values)` 和 `analyze(source, packet)`。求值器对 AST 的前置条件是：该 AST 为受控编译器的输出；求值器并不验证调用方任意构造的语法树。对于支持的 Python 输入形式，`analyze` 返回结构化的完整报告或拒绝报告。命令行接口通过 `--source` 和 `--packet` 路径调用同一操作，并且仅在结果为 `EVALUATED` 时返回退出状态零。

实现不会在分析过程中调用模型、写入仓库或执行外部行动。将返回报告写入存储的调用方，创建的是自己的制品表示。命令行接口只读取明确提供的来源和包，并将结果写到标准输出。这些本地行为并未实现通用执行适配器或授权适配器。

## 3. 来源身份与完整规则单元 {#3-source-identity-and-complete-rule-units}

来源是最多65,536字节的有效 UTF-8 文本，所给媒体类型为 `text/plain`。包中的 `source_sha256` 是这些精确字节的 SHA-256 摘要，使用既有 `sha256/raw-bytes-v1` 域。在计算哈希或验证选择器之前，不进行大小写折叠、Unicode 规范化或换行改写。

每个非空的来源物理行要么是保留上下文的 `NOTE <human text>` 行，要么是受控规则单元。允许空行。受控规则单元是以下形式的完整物理行：

```text
RULE reading_id: expression
```

标识符使用 ASCII `[a-z][a-z0-9_]{0,31}`。大写标记和规则算子属于这一受控语言。带缩进的标记、拼写错误的标记及其他非空行形式均不受支持；它们不会作为无害的周围文字从清单中消失。不会通过移除 UTF-8 BOM 来修复标记。单独的回车符和 NUL 字节不受支持。选择器 `[start, end)` 从来源开头按字节计数。它包括整个规则行，但排除行末的 LF 或 CRLF；最后一行可以没有行终止符。选定字节解码后须与包中的 `quote` 完全一致。UTF-8 字符边界和物理行边界都具有实质意义。

**SBR-R003.** 给定来源中的每个受控规则单元必须（MUST）恰好对应一项给定解读，且具有相同标识符和覆盖完整单元的字节选择器。

**SBR-R004.** 操作必须（MUST）拒绝以下情形：来源摘要不符；选择器越界或不是整数；选择器截断 UTF-8 字符或物理规则行；引文不符；单元身份重复；单元缺失；或存在额外解读。

这种完整单元规则比仅检查选定子串能否解析更严格。例如，前缀 `member AND trained` 可以解析，但从后面仍接有 `UNLESS suspended` 的行中只选取这一前缀，会丢失实质性的例外。前缀字节精确匹配，并不能证明完整规则已被保留。

`NOTE` 行的文字仍作为来源上下文可供查阅。本配置不解释其中的标点、Markdown、HTML、指令或普通语言声明。注释不是编译器的额外前提。特别是，对原始来源的绑定并不表明某条链接在渲染页面中可见或可用。未来的渲染来源适配器需要按 CTX-R017 指定自己的阅读器并记录渲染观察；来源中的一个 URL 字符串不足以证明这种性质。

规则清单仅对于这一明确标记的有限来源语言是穷尽的。它不能确立来源完整、意义完整，或所有可能解读均已覆盖。提供更短或不同的来源会产生不同的字节身份，并要求在本分析器之外单独给出来源选择依据。

## 4. 带类型的包与保留的解读 {#4-typed-packet-and-retained-readings}

文件包是最多131,072字节的严格 UTF-8 JSON 对象，其顶层键恰好如下：

| 键 | 类型与含义 |
| --- | --- |
| `schema` | 精确字符串 `kc-semantic-bridge/1` |
| `source_sha256` | 精确的来源字节摘要 |
| `source_media_type` | 精确字符串 `text/plain` |
| `interpretation_set` | 精确字符串 `alternatives` |
| `observations` | 将零至八个观察标识符映射到布尔观察记录的映射 |
| `readings` | 含一至四条带归属标注的解读记录的数组 |

**SBR-R005.** 完整的包读入与分析操作必须（MUST）拒绝任意深度的重复成员名、未知记录成员、非有限数值标记、无效 Unicode，以及类型替换，例如用布尔值作为字节偏移量。

包结构严格，并不意味着这个包就是完整的 `KCObservation/v1` 交换记录。持久证据还需要 STA-R002 和 KOP-R013 所要求的方法、观察者、时间、标准及精确的评估对象绑定。运行记录可以引用来源、包、实现和报告的字节，而不假装一个来源摘要就提供了所有其他字段。

### 4.1 观察与指称对象 {#41-observations-and-referents}

每项观察都有 `referent`、`type` 和 `state`。指称对象描述是给定的1–256个 Unicode 码位文本，不含 U+0000–U+001F 控制字符；`type` 必须恰为 `boolean`；状态为 `known`、`unknown` 或 `withheld`。已知观察恰好多一个 `value` 成员，其中包含 JSON 布尔值。未知和不予披露的观察不携带取值。

已知表示*作为本次计算的固定值提供*，而非已在现实世界中独立确立。未知和不予披露在求值时均允许任一布尔值，但报告仍区分它们的可用性状态。不予披露不表示不存在、为假或经调查仍未知。如果所引用布尔观察的含义确实不适用，就需要另一种受支持的映射；本配置不提供从 `not_applicable` 到假的自动转换。

共享变量由观察身份决定，而不是由相似的指称对象字符串决定。如果两个局部原子名绑定到同一观察，它们在每个世界中都会获得相同值。反过来，两个不同的观察身份不会仅因给定描述的文本相同，就变成同一身份。这样分配身份是否适当，是一项输入假设。

### 4.2 解读记录 {#42-reading-records}

每项解读恰好包含 `id`、`start`、`end`、`quote`、`attribution` 和 `bindings`。其标识符与来源中的完整规则单元一致。归属标注恰好包含 `agent` 描述和 `discourse`；前者具有与指称对象描述相同的文本限制，后者支持的值为 `asserted`、`quoted` 和 `hypothetical`。绑定将表达式中的每个局部原子映射到已有观察标识符。观察身份和局部原子使用与解读身份相同的有界 ASCII 标识符语言。

**SBR-R006.** 绑定必须（MUST）覆盖表达式使用的全部且仅有的局部原子，共享观察身份必须（MUST）在整个求值过程中保持关联。

解读数组提供针对同一个建模问题的备选解读。它不是若干分别断言规则的合取。任何解读都不会因其顺序、归属标签、表面上的流畅性或答案是否方便而得到优先地位。支持的是扁平归属标注；嵌套引文、认可链和经过认证的权限不会被默默压平为这种形式。

**SBR-R007.** 实现必须（MUST）保留每项给定解读及其归属标注和绑定；若某项必需解读无法支持，则必须阻止对解释集合的完整求值。

这三个话语标签不改变布尔计算。它们限定记录如何描述其来源。计算被引用表达式或假设表达式的后果，不等于将其采纳为当前政策。即便表达式标为 `asserted`，也不会自动成为真实断言。

## 5. 受控表达式语言 {#5-controlled-expression-language}

支持的语法如下：

```text
expr      := or_expr [ UNLESS or_expr ]
or_expr   := and_expr { OR and_expr }
and_expr  := unary { AND unary }
unary     := NOT unary | "(" expr ")" | TRUE | FALSE | atom
atom      := ASCII lowercase identifier
```

`NOT` 的结合优先级高于 `AND`，之后依次为 `OR` 和 `UNLESS`。括号指定不同的作用域。受控算子 `a UNLESS b` 定义为 `a AND NOT b`。这是对此形式片段的定义，而不是对英语词语“unless”或其俄语、汉语对应表达的普遍分析。包含两个未用括号区分的 `UNLESS` 算子的序列不受支持。带括号的嵌套具有所声明的布尔含义。

**SBR-R008.** 解析必须（MUST）消耗整个表达式并保留语法中各算子的作用域，不得忽略无法识别的前缀、后缀或必需构造。

每个表达式最多允许128个语法树节点，语法树深度最多为16。输入准备还限定表达式最多4,096个字符、512个词法标记，以及最多32层语法嵌套。括号不产生语法树节点，因此嵌套上限与树深度上限彼此不同。ASCII 空格和制表符分隔标记；整个规则仍须占据来源中的一个物理行。不支持的算子、格式错误的表达式和超出这些有限边界的表达式会产生明确诊断，而不是被截断的公式。解析器的精确结果代码区分超出支持语言的表示与格式错误的包；两者均不产生经求值的真值。

本配置不包含量词、数值比较、量、单位、时间算子、模态义务、过程、媒体解释或自动指称消解。这类内容可以作为未评估的上下文保留在来源中。当所请求操作需要它们时，仅靠本配置无法满足请求。添加一个名为 `verified_permission` 的布尔原子，并不会实现权限检查器；这只是添加了另一个给定布尔假设。

## 6. 可能世界语义与受保护观察 {#6-possible-world-semantics-and-protected-observations}

令 \(O\) 为有限的观察身份集合。世界是一个函数 \(w:O\to\{0,1\}\)，它与每个给定已知值一致。令 \(W\) 包含所有这样的世界。未知和不予披露的值可自由取值，同时在包与报告中保留各自不同的状态。因此，\(1\leq |W|\leq 2^8=256\)。特别是，零项观察会给出一个空赋值，而不是空域。

对于解读 \(r\)，令 \(b_r\) 将其局部原子映射到观察身份，令 \(\varphi_r\) 为解析后的表达式。它在一个世界中的值为

\[
v_r(w)=\llbracket\varphi_r\rrbracket(w\circ b_r).
\]

求值器使用普通布尔常量、否定、合取和析取，以及所声明的 `UNLESS` 展开规则。所有解读都使用同一个 \(W\)。观察标识符按字典序排列；笛卡尔积中，每项自由观察的假值排在真值之前，每项已知观察则只使用其唯一给定值。解读按来源单元顺序报告。受保护的计算观察包括：每项解读的有序真值表、其可能值集合、这些集合的并集，以及解读在同一世界中是否存在分歧。

定义

\[
V_r=\{v_r(w):w\in W\},\qquad
V=\bigcup_r V_r.
\]

报告的真值在 \(V=\{1\}\) 时为 `TRUE`，在 \(V=\{0\}\) 时为 `FALSE`，在 \(V=\{0,1\}\) 时为 `UNDETERMINED`。不确定性和任何保留的备选解读都不会被默默丢弃。即使某些观察仍为未知，也可以有条件地支持一个恒定结果；例如，对于同一观察的两个可能值，`p OR NOT p` 都为真。

解读分歧意味着

\[
\exists w\in W\;\exists r,s:\;v_r(w)\ne v_s(w).
\]

仅比较可能值集合是不够的。在观察未知时，`p` 和 `NOT p` 两项解读的可能值集合均为 \(\{0,1\}\)，但它们在每个世界中都不一致。反过来，两个等价公式可能在每个世界中都一致，即使措辞或语法不同。这种计算一致性不能确立它们全部人类含义的等价性。

**SBR-R009.** 操作必须（MUST）枚举每个允许的世界，在同一观察赋值下对每项保留解读求值，并通过同一世界中的比较报告分歧。

有限的操作解释域由二元组 \((r,w)\) 构成，且至少有一项解读和一个世界。至少指定了一项实质性的计算观察，即每条保留规则的布尔值。这些条件避免了在空域或没有实质问题时声称充分性。它们确立的是本次计算的域，而不是《意义桥梁》第4.2节为更广泛的充分性所要求的来源到解释前提的真实性。

在所述输入和语法边界内，有限计算会终止。其工作量受来源与包验证，以及最多四项解读、256个世界、每项解读128个语法节点的限制。该界限涉及所声明的表示；它不是对不受限制的语言理解所作的效率或终止性声明。

## 7. 结果、不确定性与损失 {#7-results-uncertainty-and-losses}

本地结果代码 `EVALUATED`、`INVALID` 和 `UNSUPPORTED` 属于本分析器。它们不是对规范状态模型词汇表的扩充。下表说明各代码对本地操作能够支持什么解释。

| 分析器结果 | 操作结果状态与停止原因 | 可支持的解释 |
| --- | --- | --- |
| `EVALUATED` | `success`, `completed` | 全部保留的受控规则均已在指定有限世界中求值；`UNDETERMINED` 是有效的计算结果 |
| `INVALID` | `refused`, `precondition_not_met` | 某项必需输入条件或来源绑定条件未满足；没有可用的经求值真值 |
| `UNSUPPORTED` | `refused`, `precondition_not_met` | 给定表示或表达式超出本配置；没有可用的完整求值 |

要求一个确定答案的调用任务仍可能处于 `unresolved`，原因为 `clarification_needed`，即使本地计算已经成功完成并返回了 `UNDETERMINED`。这里评估的是不同对象，使用的是不同标准。报告不会把计算成功转化为下游任务成功。

报告模式为 `kc-semantic-bridge-report/1`。对于已完成求值的包，它包括精确的来源摘要、保留的观察记录、按来源排序的解读、有序的 `world_assignments`、`valuation_count`、合并后的 `possible_values`、`truth` 和 `reading_disagreement`。每项解读包括其身份、归属标注、绑定、范围、引文、AST、`table_bits` 和可能值。位置 \(i\) 的比特记录该解读在世界 \(i\) 中的布尔结果，假值编码为 `0`。当两个值都出现时，可能值数组先列假，后列真。AST 使用 `const`、`atom`、`not`、`and`、`or` 和 `unless` 节点，并保留语法规定的作用域。

独立列出的 `source_binding` 和 `controlled_parsing` 检查在各自的精确范围内使用 `VERIFIED` 或 `NOT_VERIFIED`。随后出现表达式不受支持的结果，无须抹去已成功完成的字节绑定检查，但不会提供经求值的真值。自然语言保真度、归属真实性、现实世界真值和当前权限仍为 `NOT_ASSESSED`；在规范状态词汇中，这表示检查结果为 `unknown`，并附有指出未执行评估的原因。它既不是豁免，也不是失败判定。分析器始终报告 `effects_authorized: false`。

**SBR-R010.** 输出不得（MUST NOT）将 `NOT_ASSESSED` 表示为 `pass`，不得将计算所得 `TRUE` 等同于当前许可，也不得在任何必需解读验证失败后给出经求值的真值。

这里损失与不确定性具有不同含义。未知或不予披露的输入以及保留的备选解读，保存了模型中的可能性。不支持的构造位于形式化范围之外。未经解释的周围文字是保留的来源上下文，它与公式之间是否存在忠实对应关系尚未评估。来源修订版、归属标注、绑定或解释集合发生变化，就形成新的输入；旧评估不会自动继承。

本配置不提供部分准入模式。想对更小解释集合求值的消费者，需要另行标识请求并提供来源选择依据。丢弃验证失败的备选解读，却保留原先的完整覆盖声明，违反本配置。

## 8. 原创示例详解 {#8-worked-original-examples}

以下示例是为说明本配置而新写的示例，并非恢复的历史观察，也不是测得的提取结果。英语、俄语和简体中文文字用于检查明确受控规则周围不同的 UTF-8 字节位置。它们的翻译属于示例性的作者草稿；分析器不验证跨语言保真度。每个来源中的文字都占一行，以 `NOTE` 加一个空格开头。

| 语言 | 形式片段之外的周围文字 |
| --- | --- |
| 英语 | In this example, a member who has completed training meets the camera-lending condition unless lending is suspended. This describes the example's condition and grants no real-world access. |
| 俄语 | В этом примере участник, прошедший обучение, соответствует условию выдачи камеры, если выдача не приостановлена. Это описание условия примера, а не действующее разрешение. |
| 简体中文 | 在本示例中，已完成培训的会员符合借用相机的条件，但借用服务暂停时除外。此陈述描述示例中的条件，不授予现实中的使用权限。 |

每个独立来源都包含以下完整受控行：

```text
RULE lending: (member AND trained) UNLESS suspended
```

该解读归属于示例作者，标为 `hypothetical`。三个局部原子绑定到三个不同的给定布尔观察。当 `member=true`、`trained=true` 且 `suspended=false` 时，计算值为真。当 `suspended=true` 时，计算值为假。如果是否暂停为未知或不予披露，则两个值都仍有可能；两种可用性状态保持区别。没有任何一种情形确立了借出真实相机的当前许可。

歧义示例则提供两个完整单元：

```text
RULE broad: (member OR guest) AND trained
RULE narrow: member OR (guest AND trained)
```

它们是明确给定的备选解读，而非提取模型发现的解读。在同一个世界 `member=true`、`guest=false`、`trained=false` 中，两者的值不同。报告保留二者，报告分歧，并将合并真值保留为未确定。选择更宽松的结果会改变解释集合，需要在本次计算之外提供新的依据。

使用 `FORALL`、数值比较或不可用的媒体派生条件的规则，不能通过默默删除该部分而获得支持。一个受支持原子可以代表关于媒体来源的给定布尔假设，但该假设不提供图像检查证据，也不能满足要求图像本身的任务。

## 9. 有限验收配置 {#9-finite-acceptance-profile}

验收依据的是固定的义务清单，而不是不断扩展的类似示例集合。测试实现可以对案例分组，但其报告必须标识实际测试的精确输入、获得预期结果的独立方法以及实现修订版。验收清单如下：

| 义务 | 必需的阳性或对抗性观察 |
| --- | --- |
| 完整来源绑定 | 精确摘要和完整行通过；改变的字节、错误引文、截断的前缀或后缀、无效 UTF-8 边界及缺失、重复或额外单元均不产生已求值结果；未知或格式错误的行标记不被忽略 |
| 严格的带类型包 | 受支持记录通过；未知成员、重复 JSON 键、错误标量类型以及值与状态之间的矛盾被拒绝 |
| 算子作用域与例外 | 独立布尔表对否定、优先级、括号及 `UNLESS` 给出一致结果；删除例外会在一个可区分的世界中改变实质计算观察 |
| 共享观察 | 作为别名的局部原子获得同一个关联值；当 `p AND NOT q` 中两个原子都绑定到同一个未知观察时，表达式恒假 |
| 备选解读 | 全部给定解读均被保留；当共享观察未知时，`p` 和 `NOT p` 报告同一世界中的分歧，尽管可能值集合相等 |
| 非空计算 | 零观察的常量使用一个世界；空解读集合被拒绝，绝不据此认证任意答案 |
| 未知与不予披露 | 两者均允许两个值，同时保留各自不同的可用性状态；两者均不变成给定的假值 |
| 归属边界 | 断言、引述和假设记录保留其标签，不改变运算，也不发出许可；给定的错误断言不会被认证为世界真相 |
| 不受支持的输入 | 必需但不受支持的表达式或归属结构阻止完整求值，即使其他解读各自受支持也一样 |
| 有限边界 | 声明的边界及越界案例均有明确结果；求值不会截断来源、表达式、世界或备选解读 |
| 原创多语字节 | 三个示例来源通过精确 UTF-8 字节选择器绑定，并产生声明的受控结果；这不推出任何翻译准确性结论 |
| 组合边界 | 已求值结果保留尚未评估的权限，不能自行满足下游当前授权标准；必需媒体或嵌套归属仍属不支持或已委托事项。本配置不实现下游准入 |

**SBR-R011.** 测试集必须（MUST）检验这些义务并保留对抗性结果，而不能为了迁就实现而修改声明的预期结果。

范围更广的 SEM-R015 测试集还要求嵌套引文、呈指令形式的反例以及必需媒体缺失的情形。本配置仅处理扁平归属标注和布尔公式。因此，其验收记录将这些情形标识为不支持或委托处理；它不会把嵌套引文重新标为扁平断言，或把图像重新标为已验证的布尔值，以此声称完整符合性。

成功的有限检查仅确立在其声明输入上的行为。它们不测量提取保真度，不发现每一种可能解释，不鉴别来源真伪，也不确立相对于其他方法的因果优势。同一控制器上的另行指定审查者或独立构造的判定基准，仍属于内部技术评估，而不是外部同行评审。

## 10. 与制品及未来配置的组合 {#10-composition-with-artifacts-and-future-profiles}

经过求值的公式可以依照既有[《制品登记册》](../artifact-registry/SPECIFICATION.md)，成为制品中被引用的组件。包含它的制品仍需要自己的身份、目的、要求、约束和证据。角色可以引用一个条件而不向其承担者授予权限；技能可以引用一项检查而不证明执行者能力；胜任能力需要对具体主体进行实际评估；方案蓝图需要有效的组件接口；约束需要其来源、适用性和执行保障方法。这些是 REG-R009、REG-R015 和 KCC-R007–KCC-R017 的义务，而不是 `EVALUATED` 自动带来的后果。

只有在精确来源和必需依赖均被保留时，报告才能支持一个[《语境包》](../context-package/SPECIFICATION.md)。包的需求覆盖、对接收者的适用性以及实际交付，仍分别接受评估。检查过的来源选择器既不是渲染后可见的链接，也不是接收者已经检查来源的证明。

未来配置可以增加量、时间、量词、更丰富的归属标注或媒体，但每项新增内容都需要明确的类型、语义、映射、资源限制，并在可行时提供可执行检查。引入这些内容不是仅修改本配置元数据就能完成的升级。不受支持的必需材料仍按 KCC-R013 阻止使用；保留的不透明字节不能确立语义支持。

这一有界交付成果完成了计划中的《语义桥接》在来源绑定和受控计算方面的部分。一般的人类意义到形式表示转换、提取保真度、更广泛的制品集成以及现实世界准入工作，仍分别保有自己的范围。

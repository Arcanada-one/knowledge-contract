# 知识操作契约 {#contracts-for-knowledge-operations}

**作者：**Pavel Valentov · **出版版本：**1.1

## 1. 目的与符合性 {#1-purpose-and-conformance}

本文是一组架构要求。互操作性需要具名的表示配置；已实现的交换子集仅限于[观察、变更事件和配置通告](../status-model/SPECIFICATION.md#8-bounded-exchange-profile)，而[书籍包配置](../book-package/SPECIFICATION.md)具有自己的模式。这并不意味着已有完整契约的传输格式或已部署的运行时。

操作契约说明何时可以执行操作、保留或改变什么、允许哪些结果，以及哪些证据支持所报告的结果。其承诺只对声明的输入、要求修订版和环境成立。完成一个操作不一定满足整个工作项。

大写要求用语遵循 [BCP 14](../../../../../reference/bibliography/BIBLIOGRAPHY.md#requirement-language)。

**KOP-R001.** 本文规定操作语义；符合规范的适配器还必须（MUST）明确其表示配置和可执行检查。

[变换论文](../../../../../papers/constrained-transformations/PAPER.md)提供条件式形式模型。

## 2. 共通契约记录 {#2-common-contract-record}

**KOP-R002.** 每个操作定义必须（MUST）指明以下内容：

| 字段分组 | 必需内容 |
| --- | --- |
| 定义 | 操作名称、不可变的定义版本，以及支持的输入和输出配置 |
| 目的 | 局部目标及其与工作项和要求修订版的关系 |
| 输入 | 精确的制品修订版、基数、相关环境以及缺失输入时的行为 |
| 前置条件 | 授权并使尝试能够进行的条件；检查方法与信任边界 |
| 不变量 | 在操作声明的可观察范围内始终保留的性质 |
| 后置条件 | 每种允许结果所附带的条件，包括部分完成和拒绝 |
| 效果 | 读写范围、外部效果、重复策略、核对和补偿行为 |
| 资源 | 预算、截止时间、最大尝试次数和停止规则 |
| 证据 | 对象绑定、观察方法和评估器的限制 |

**KOP-R003.** 前置条件、不变量和后置条件必须（MUST）保持分离。

较晚发生的成功观察，不能确立不变量在此前每一步都成立。关于输出形状的证据，不能确立其语义正确性。

## 3. 操作族 {#3-operation-families}

以下功能族用于组织实现。它们代表职责，而不是要求部署独立服务。

| 操作族 | 保留义务 | 主要失败方式 |
| --- | --- | --- |
| 获取与寻址 | 来源身份、版本、定位符和获取溯源 | 将不可用或被替换的来源视为已经观察到 |
| 解释与提取 | 归属、否定、量词、例外和未决理解 | 来源断言变成无条件事实 |
| 搜索与比较 | 查询语义、范围、候选项溯源和比较标准 | 将相似性变成等价性或完整性 |
| 选择与组合 | 强制依赖闭包、联合身份、覆盖和总预算 | 缩短内容时必要条件消失 |
| 变换与呈现 | 声明的受保护观察、表示要求和损失 | 用可读描述替代必需媒体 |
| 交付与确认 | 接收者、表示、修订版和交付观察 | 将定位符误认为已经交付的内容 |
| 规划与执行 | 工作绑定、能力、权限、尝试身份和效果 | 将计划或超时误认为已知执行结果 |
| 评估与修订 | 精确对象、方法、新证据和保留的历史 | 将判断结果转移到另一修订版 |
| 存储与复用 | 固定的依赖版本、当前适用性、授权和失效处理 | 缓存命中绕过准入决定 |

**KOP-R004.** 实现可以（MAY）在这些操作族内部提供范围更窄的操作。

**KOP-R005.** 每个对外提供的操作必须（MUST）说明它承担哪些职责、委托哪些职责。

**KOP-R006.** 它不得（MUST NOT）将必要职责隐藏在适配器之间的空隙中。

## 4. 组合 {#4-composition}

**KOP-R007.** 对于先 A 后 B 的操作组合，A 产生并供 B 使用的每个获准成功输出，都必须（MUST）满足 B 的前置条件。

**KOP-R008.** 共同不变量必须（MUST）在两次转换中均得到保留。

即使每个操作都通过了各自的独立测试，只要尚未确立上述关系，组合仍然是未决的。

**KOP-R009.** 语义变换必须（MUST）声明其受保护观察，例如命题的真值条件、过程步骤顺序，或者图示的标签与连接关系。

这些观察相等，比所有意义都相等是更窄的声明。

**KOP-R010.** 有损变换必须（MUST）保留损失记录。

只有在重构已经得到论证的声明定义域内，才可以声称存在逆变换。

带有效果的操作需要独立的组合政策。围绕一条记录的本地事务不会使外部服务具有原子性。

**KOP-R011.** 派发后的超时必须（MUST）保留效果未知状态，直到领域特定的核对确立实际发生了什么。

## 5. 结果与证据 {#5-outcomes-and-evidence}

结果词汇包括 `success`、`partial`、`refused`、`failed` 和 `unresolved`，其定义见[状态模型](../status-model/SPECIFICATION.md#3-canonical-dimension-vocabularies)。`ready` 是生命周期或运行阶段，而不是操作结果。停止原因解释控制为何结束；效果观察描述对外部变化已经知道的内容。

**KOP-R012.** 这些维度不得（MUST NOT）合并为单一的完成标志。

比较操作可以通过报告“不等价”而成功完成。拒绝可以正确执行约束，同时仍未满足用户的原始目标。

**KOP-R013.** 证据必须（MUST）标识定义版本、输入和输出修订版、尝试、相关要求、检查器及检查结果。

**KOP-R014.** 继承的观察必须（MUST）指出允许继承的前提。

**KOP-R015.** 对所提供断言的检查与对独立观察条件的检查，必须（MUST）能够区分。

## 6. 验收用例 {#6-acceptance-cases}

**KOP-R016.** 符合规范的适配器必须（MUST）检验以下情形：有效输入；无效输入；未知的强制前置条件；受保护性质被违反；部分输出；预算耗尽；过时的要求修订版；以及对于带有效果的操作，效果不确定的超时。

**KOP-R017.** 组合测试必须（MUST）包括一种 A 的有效输出，但它违反 B 的前置条件。

预期结果是拒绝或组合未决，而不是自动继续。

[依赖与交付研究](../../../../../engineering/studies/dependency-closure-and-package-delivery/STUDY.md)提供有限闭包重放。[可执行投影研究](../../../../../engineering/studies/executable-projections-and-revision/STUDY.md)提供有限范围内的投影和修订证据。这些有限结果并不认证本规范中的每个操作族。

## 7. 表示与演化 {#7-representation-and-evolution}

该架构不要求为每个操作新增一种全局制品类型。版本化定义可以表示为可寻址记录，并由尝试和证据引用。

**KOP-R018.** 历史示例封套继续按原始配置解释；适配器将它们映射到本操作族时，必须（MUST）披露任何损失。

操作定义变化会创建新版本。尝试保留其当时采用的定义。依据新定义进行重新评估，是一次新观察，而不是追溯性地声称旧尝试遵循了新定义。参见[知识演化](../knowledge-evolution/SPECIFICATION.md)与[状态模型](../status-model/SPECIFICATION.md)。

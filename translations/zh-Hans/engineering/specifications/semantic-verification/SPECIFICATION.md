# 语义验证：主张、检查与证据 {#semantic-verification-claims-checks-and-evidence}

**作者：**Pavel Valentov · **出版版本：**1.1 · **状态：**研究草稿

## 1. 目的与符合性 {#1-purpose-and-conformance}

一项检查本身可能正确，却仍被用来支持并非它所检验的主张。摘要比较针对的是已标识的字节。证明针对的是其声明的模型。程序测试针对的是实际执行的实现与输入。这些观察中，任何一项都不能单独确立来源忠实性、当前许可或实际效益。

本规范定义如何准备和评估验证包：这类记录使上述关联能够被检查。它将[《证据与证伪》](../../../../../papers/evidence-and-falsification/PAPER.md)转化为操作要求，并复用[《状态模型》](../../../../../engineering/specifications/status-model/SPECIFICATION.md)、[《知识操作》](../../../../../engineering/specifications/contract-family/SPECIFICATION.md)中的证据义务，以及现有的[主张—证据索引](../../../../../engineering/studies/evidence-index.json)。它不另设一个状态裁定权威。

本文规定验证包的准备与评估要求，并提供一个有界有限配置，用于检查能否从保留的观察中恢复某项已声明的评估。它不规定通用自然语言验证器，不鉴别所提供事实的真实性，也不确立某个已部署系统符合规范。声称具有互操作性的序列化方式或运行时，需要一个具名的表示配置以及其自身已实现的接口。

大写要求用语遵循 [BCP 14](../../../../../reference/bibliography/BIBLIOGRAPHY.md#requirement-language)。

**SVR-R001.** 符合性主张必须（MUST）标明其适用的要求、表示配置、确切实现修订版和已评估范围。

符合有限迁移配置的范围，比符合验证包准备要求的范围更窄；两者都不能确立未经考察领域中的科学真理。

## 2. 主张、对象与评估维度 {#2-claims-subjects-and-assessment-dimensions}

主张是具有明确解释和适用范围的命题。其对象可以是数学模型、文档修订版、执行尝试、实现构建或比较结果。关于同一制品的多项主张可能需要不同的证据。

评估将一项具名准则应用于该对象。规范检查结果为 `pass`、`fail`、`unknown` 和 `not_applicable`，定义见 STA-R002–R004。已知评估结果为 `unknown`，与缺少评估记录不同。`not_applicable` 结果需要有已证明适用的准则豁免规则；它不能替代缺失的信息。

**SVR-R002.** 每个验证包必须（MUST）将一项已标识的主张或一个明确枚举的主张集，与不可变的对象及准则修订版、声明的量词、假设、适用范围和预期结论绑定。

**SVR-R003.** 覆盖多个属性的验证包必须（MUST）保留各属性的单独结果、依据与局限，并且必须（MUST）声明任何汇总决策规则。

例如，来源忠实性、形式计算、现实世界中的真实性、授权和任务成功是不同的属性。《语义桥接》的 SBR-R010 保留了这条边界：计算所得的 `TRUE` 不是授权，`NOT_ASSESSED` 也不是评估通过。复用该配置，并不要求将其领域专用输出重新命名为规范检查词汇。

总体失败也会丢失信息。属性向量 `(pass, fail)` 与 `(fail, pass)` 具有相同的合取结果，却具有不同的依据和修复义务。

## 3. 验证包 {#3-verification-packet}

以下是逻辑记录模型。只要各记录的身份和关系明确，配置可以将其序列化为多个相互关联的记录。

| 字段组 | 必需含义 |
| --- | --- |
| 主张 | 确切陈述、类别、量词、预期结论，以及被排除的更强结论 |
| 对象 | 制品、模型或尝试的身份；不可变修订版；相关输入、输出与构建的身份 |
| 准则 | 要求或评估规则的修订版；被评估属性；验收与不适用规则 |
| 配置与定义域 | 支持的表示、载体或总体、准入规则、上下文、时间范围及排除项 |
| 假设 | 数学前提、提供的事实、信任依赖及无法取得的信息 |
| 方法 | 证明审查程序、可执行命令、测试设计、忠实性评分准则或比较协议 |
| 判定基准（oracle） | 如何证明预期答案合理；其输入，以及与结果生成方共有的依赖 |
| 干预 | 不利案例中的实质性变化；未改变或仅作无关变化的阳性对照 |
| 有限用例清单 | 基数公式、边界、计划用例、实际尝试用例、覆盖范围及相关性局限 |
| 实际观察 | 原始记录、观察者、相关时间、环境、确切执行与输出；或者明确说明未曾运行 |
| 评估 | 各属性的结果、推理、反向证据、局限及任何未解决义务 |
| 迁移 | 原对象与新对象、保留的观察、固定准则，以及允许继承的前提 |
| 审查 | 确切受审字节、审查者、审查者可获得的信息，以及实际独立性边界 |
| 修订与处置 | 保留的前一版本、改变的主张、理由、受影响结论及后续状态 |

**SVR-R004.** 验证包必须（MUST）提供 STA-R002 和 KOP-R013 要求的观察绑定，并且必须（MUST）按照 STA-R003 和 KOP-R015 的要求，将提供的断言与独立观察到的条件区分开。

**SVR-R005.** 无法取得的强制观察必须（MUST）明确保持为未解决并注明原因；不得（MUST NOT）将其缺失转换成正面评估或不适用豁免。

**SVR-R006.** 用于支持评估的每一处证据引用必须（MUST）标明相关记录、不可变内容身份及其在记录中的位置，精确到足以重建所声明的推理。

JSON pointer 可以标识 JSON 记录中的某个结果。确切的来源章节可以标识证明前提。只链接整个仓库，而没有相关修订版和主张位置，并不充分。公开研究的主张使用现有的证据索引和来源记录；导航链接并不是经验证据的论证。

记录完整性、真实性和实质性支持是不同的问题。完整的验证包可以诚实地得出 `unknown`。格式错误的包是表示或准备方面的失败；它不表明关于对象的科学主张为假。

## 4. 准备与评估程序 {#4-preparation-and-assessment-procedure}

首先确定主张，以及能够将它与合理的替代解释区分开的证据。在查看决定性结果之前，固定解释、输入规则和失败准则。随后选择针对该主张的方法，保留其输入，并且只执行获准的有界操作。评估观察到的结果时，不改写先前的准则。

**SVR-R007.** 验证包必须（MUST）保留受评估的主张与程序修订版、预期结果以及所有实质性偏离；在得到结果之后作出的变更必须（MUST）创建可标识的后继记录，而不能覆盖先前的评估。

**SVR-R008.** 判定基准的描述必须（MUST）披露共享的输入、算法、标注，以及其他可能使结果一致仅仅重复同一错误的依赖。

不同的代码仍可能依赖同一份错误的来源标注。使用同一算法再次运行，只能确立在其条件下的可复现性；它本身不为预期答案提供第二份论证。

**SVR-R009.** 声称是定理反例的案例必须（MUST）满足每一项已声明的前提并违反结论；违反前提的案例必须（MUST）归类为边界案例或实现测试。

**SVR-R010.** 当有用性或成功准入属于主张的一部分时，评估必须（MUST）同时包括适用的阳性对照及相关的不利对照。

永远拒绝的系统可以满足一项狭窄的排除性质，却毫无用处。反过来，一项对照失败，也不是每个操作都失败的证据。评估应标明该观察影响的是哪一项主张。

**SVR-R011.** 在报告修正或新运行时，原始输入、输出、失败案例、与比较对象持平的情况及未解决观察必须（MUST）保持可追溯。

## 5. 证据方法及其局限 {#5-evidence-methods-and-their-limits}

| 方法 | 最低评估义务 | 单凭该方法不能确立的结论 |
| --- | --- | --- |
| 证明与证明审查 | 已定义的语义、明确前提与完整推导；审查者的范围及缺口 | 前提描述的是某个特定的运行中系统 |
| 有限枚举或模型检查 | 确切的有限载体、生成器、判定基准、覆盖范围及终止界限 | 所表示空间之外的正确性 |
| 实现回归测试 | 确切程序或构建、实际执行的入口、输入，以及预期与观察到的行为对比 | 未执行路径或其他构建的符合性 |
| 来源忠实性评估 | 确切来源与表示、有依据的参照解读、保留的备选解释与遗漏 | 现实世界中的真实性或来源作者的权限 |
| 任务结果评估 | 已标识的任务、尝试、当前准则，以及相关边界上的实际输出 | 一般执行者能力或相对效益 |
| 受控比较 | 可比较的验收条件、干预、基线、结果度量及不确定性设计 | 当设计无法排除声明的竞争解释时的因果效益 |

**SVR-R012.** 验证包必须（MUST）标明这些方法中哪一种实际支持每项结论，并且必须（MUST）区分导入的生产代码、独立运行的参照模型，以及提出但尚未执行的程序。

写在规范旁边的算法并不是强制执行要求的证据。导入生产模块的测试，比脱离该模块的模型提供了更强的模块证据，但仅针对所执行的配置和用例。仅阅读源码，并不能确立执行器加载或使用了所标识的字节。

**SVR-R013.** 经验评估与比较协议必须（MUST）标明观察单位、抽样或用例选择规则、比较对象、度量、不确定性的解释、获准资源界限及停止条件。

本规范不授权任何新的模型运行、外部效果或付费实验。一项设计可以作为协议保持完整，同时其执行仍未进行。

## 6. 有限验证档案 {#6-finite-verification-passports}

有限验证档案标识被计数的空间。相同的总数可以描述互不相关的对象。以下示例说明这种区别；公式本身并不声称发生了新的运行。

| 空间 | 基数与界限 | 范围身份 |
| --- | --- | --- |
| 有向图与根集合 | 三个带标签且允许自环的顶点：\(2^{3^2}2^3=4,096\) 个图与根集合对 | 路线图实验计划中的小模型范围 |
| 布尔函数三元组 | 两个原子有四种赋值和十六个布尔函数；\(16^3=4,096\) 个有序三元组 | 同一计划中标识的另一项历史布尔函数范围 |
| 一个固定技能根集合的子集 | 十二个可选择根：固定提取依赖图的 \(2^{12}=4,096\) 个子集 | 保留的《依赖闭包》研究；这并未枚举所有图 |
| 保留观察映射与评估映射 | 四个带标签的情形；\(2^4\) 个二元观察映射和 \(4^4\) 个四结果评估映射；\(2^4 4^4=4,096\) 个配置 | 第 7 节的有限迁移配置 |

前两个范围身份由[实验计划](../../../../../roadmap/EXPERIMENTS.md#4-small-models-larger-models-and-code-under-test)规定。第三个属于[《依赖闭包》研究](../../../../../engineering/studies/dependency-closure-and-package-delivery/STUDY.md)，其保留的执行记录有自身确切的范围。它们不能彼此作为可互换的证据。

**SVR-R014.** 有限验证档案必须（MUST）记录载体、生成器、界限及基数推导，并且必须（MUST）让计算出的、计划的、已尝试的、已完成的、已拒绝的和未执行的用例计数保持可区分。

配置应声明这些计数器如何重叠。例如，依照预先固定的准则，拒绝可以是一个已完成且符合预期的负向用例，也可以是一次中断的尝试。应报告这一定义，而不是将所有结果强行纳入一个未经解释的成功总数。

**SVR-R015.** 有限验证档案必须（MUST）标明空真用例、重复或相关的配置，以及为缩减空间所使用的任何取商或抽样。

空的根集合可以是有意设置的图测试。空的经验样本不能确立有用的行为。重复标号可以提供不同的程序输入，却不构成独立的经验试验。

**SVR-R016.** 有限执行主张必须（MUST）报告实际停止规则、资源及观察到的完成情况，并且不得（MUST NOT）以计算出的基数代替已执行用例数。

## 7. 有界配置：评估迁移 {#7-bounded-profile-assessment-transfer}

### 7.1 固定评估与保留观察 {#71-fixed-assessment-and-retained-observations}

设 \(S\) 为一个非空的、已声明的评估情形集合。每个情形包含所建模属性所需的对象修订版、准则、范围、相关输入、上下文与时间。设

\[
p:S\to A=p(S),\qquad v:S\to D
\]

分别为保留观察与一个固定评估函数。在有限配置中，\(D=\{\mathrm{pass},\mathrm{fail},\mathrm{unknown},
\mathrm{not\_applicable}\}\)。这些是模型中规定的取值。它们的存在并不能确立相应的真实评估曾经实施或得到论证。

[《意义几何》命题 2](../../../../../papers/geometry-of-semantic-representations/PAPER.md#proposition-2-recoverability-requires-agreement-on-representation-fibres)已经确立了相关的分解判据。存在唯一函数 \(\bar v:A\to D\) 使 \(v=\bar v\circ p\)，当且仅当

\[
p(s)=p(t)\Longrightarrow v(s)=v(t)\qquad(s,t\in S).
\]

本规范复用该结果，不声称分解本身具有新颖性。[《知识变换》命题 4](../../../../../papers/constrained-transformations/PAPER.md#proposition-4-coherent-relations-descend-and-compose-exactly)将同一原理用于可能输出观察的集合。[《知识修订》命题 2](../../../../../papers/revision-and-governance/PAPER.md#proposition-2-checks-transfer-through-preserved-complete-inputs)规定了确定性检查结果的相关完整输入条件。结果相等仍需另行论证其可靠性。

### 7.2 最大部分恢复 {#72-maximal-partial-recovery}

无法进行全局分解，并不意味着每个已达到的观察都有歧义。对于观察值 \(a\)，定义

\[
D_a=\{v(s):s\in S,\ p(s)=a\},\qquad
U=\{a\in A:|D_a|=1\}.
\]

存在唯一的部分函数 \(\bar v_U:U\to D\)，将 \(D_a\) 的唯一元素赋予每个 \(a\in U\)。它满足 \(v(s)=\bar v_U(p(s))\)，成立范围为 \(p^{-1}(U)\)。按扩张关系，它是最大的可靠部分映射：定义在已达到观察上的每个可靠部分映射都是它的限制。因此，在能够恢复确切评估的已达到观察子集中，它的定义域是最大的。

这是现有判据的一个基本推论。在每个被选中的纤维上，值都恒定，因此该赋值良定义。反之，如果在某个已达到的 \(a\) 上定义了确切的分解函数，那么该纤维中的每个情形都必须取该函数的值；因此 \(D_a\) 是单元素集合，且 \(a\in U\)。原像 \(p^{-1}(U)\) 保留整个纤维，而不是悄悄选取一个有利的代表。

未达到的查询满足 \(D_a=\varnothing\)，位于这一定义域之外。它不会因为空真意义下的一致而获得结果。包含 `unknown` 的单元素集合被确定为该模型结果；包含 `not_applicable` 的单元素集合，并不能独立确立真实应用中的豁免规则。

**SVR-R017.** 迁移应用必须（MUST）标明固定主张、评估规则、情形定义域与保留观察，并且必须（MUST）确立 KOP-R014 要求的允许继承的前提。

**SVR-R018.** 声称能够精确部分恢复的有限诊断必须（MUST）保留所有已声明的评估区别，使用查询纤维中提供的每一个情形，并拒绝有歧义或未达到的查询。

**SVR-R019.** 报告的阻碍必须（MUST）保留至少两个位于定义域内、保留观察相同而评估值不同的情形。

一次冲突可以反驳从这些观察进行普遍迁移的提议。它并不表明每次具体执行都失败。加入先前遗漏的情形，可能使一个单元素纤维变为有歧义的纤维，因此样本结果不能证明应用模型是完整的。

### 7.3 诊断结果与应用证据 {#73-diagnostic-results-and-application-evidence}

有限参照接口区分 `determined_in_model`、`refused_ambiguous` 和 `refused_unattained`。这些值描述诊断操作，不替代四个规范评估值。具有确定结果的诊断携带模型值和相关纤维。

例如，取观察 \((0,0,1)\) 与评估 \((\mathrm{pass},\mathrm{fail},\mathrm{unknown})\)。查询 0 有歧义，查询 1 被确定为 `unknown`，查询 2 未达到。在查询 1 上报告 `unknown`，忠实保留了规定的模型结果，并不声称已经评估实际目标。

**SVR-R020.** 诊断结果必须（MUST）始终区别于评估值，也区别于证明真实目标满足模型绑定、信任假设及准则的证据。

**SVR-R021.** 真实使用中的继承主张必须（MUST）确立源对象与目标对象之间相关观察的相等性及应用条件；不得（MUST NOT）仅凭模型分解就将其报告为对目标的新观察。

两次运行可以具有相同的检索记录，而它们的消费者却使用不同的缓冲区。因此，检索完整性并不能决定某个特定消费者使用了那些字节这一主张。同样，消费者输入相同，也未必意味着当前具体授权相同。这些是构造的信息丢失示例，不是关于某个运行中消费者或授权检查失败的观察。

对于实际消费者使用的主张，应在具名评估之前的最后一个可信调用边界上观察有效输入。当后续参数可能不同时，仅对检索到的文件或更早的缓冲区取哈希并不充分。将检索回执及其摘要与消费者修订版、入口、尝试和调用绑定；保留捕获到的有效输入摘要，以及同一次调用产生的输出。标明观察者及其实际上能够证明什么。输出出现在输入摘要旁边，本身并不是输出由这些字节导出的证据。

有用的不利对照会在保留先前检索记录的同时，将一个可由判定基准区分的替代输入送到实际评估边界。必须论证预期的改变结果或明确拒绝，而不能使用消费者的答案作为它自身的判定基准。适用的匹配输入案例也必须成功。必需输入发生实质性变化之后，应保留旧观察，另外捕获新输入并明确记录恢复；不要重新标记先前的回执。相关变化与无害变化检验的是不同义务。这些对照只在观察者声明的信任假设下，支持关于具名消费者与被捕获边界的结论；当前许可和撤销仍需分别评估。

### 7.4 四情形配置的计算清单 {#74-calculated-inventory-for-the-four-situation-profile}

第 6 节的 4,096 个配置按下表划分。“仅部分”表示至少一个已达到纤维恒定，且至少一个不恒定。

| 二元观察的纤维大小 | 观察映射数 | 全局 | 仅部分 | 无确定的已达到纤维 |
| --- | ---: | ---: | ---: | ---: |
| 4 | 2 | 8 | 0 | 504 |
| 1 和 3 | 8 | 128 | 1,920 | 0 |
| 2 和 2 | 6 | 96 | 576 | 864 |
| 总计 | 16 | 232 | 2,496 | 1,368 |

这些是计算出的基数。对于恒定观察，四个恒定评估映射可行，其余 252 个不可行。对于一加三的划分，单元素纤维总是确定的，而三元素纤维在 256 个评估映射中的 16 个上恒定。对于二加二的划分，两个纤维都恒定的有 16 个映射，恰好一个恒定的有 \(2\cdot4\cdot12=96\) 个，两个都不恒定的有 \(12^2=144\) 个。乘以表中列出的观察映射数，便得到该表。

参照判定基准可以独立枚举从两个观察标签到四个评估值的 \(5^2=25\) 个部分映射，其中第五个选项表示未定义。每个候选映射都必须在所有未达到标签上保持未定义，并在它有定义的每个情形上与 \(v\) 一致。被接受的候选映射按扩张关系具有唯一的最大部分映射；诊断结果与此映射进行比较。在每个配置上测试所有候选项，共产生 102,400 次候选映射检查。这是判定基准的工作量，不是 102,400 次独立观察或额外的评估配置。

在每个配置中查询两个标签，在同一空间上产生 8,192 次观察查询：2,952 次确定、4,728 次有歧义、512 次未达到。恒定观察映射贡献 \(2\cdot4=8\) 次确定查询，一加三划分贡献 \(8(256+16)=2,176\) 次，二加二划分贡献 \(6(2\cdot4\cdot16)=768\) 次。只有恒定映射会留下未达到标签，贡献 \(2\cdot256=512\) 次此类查询。这些查询计数描述的是相同的配置，并未增加独立试验。

在将这些计算出的计数描述为观察到的程序结果之前，必须有执行回执。即使完整运行这一空间，测试的仍然只是有限模型；它不会发现遗漏的现实情形，不会鉴别模型值的真实性，也不会确立不受限制的语义验证。

## 8. 失败行为与验收用例 {#8-failure-behavior-and-acceptance-cases}

**SVR-R022.** 表示配置必须（MUST）区分格式错误的输入、不支持的表示、缺少必需证据、资源耗尽，以及实质性负面评估，并使用现有状态维度，不得悄悄合并这些含义。

**SVR-R023.** 未完成程序后产生的结果必须（MUST）标明未执行范围及停止原因，并且不得（MUST NOT）声称具有穷尽覆盖。

**SVR-R024.** 符合性验证包必须（MUST）标明下列哪些验收用例已经执行、它们确切的预期与观察结果，以及任何不在所声称配置范围内的用例。

| 用例 | 必需区别或预期行为 |
| --- | --- |
| 确切对象与准则 | 绑定相符才允许评估；实质性输入或准则改变需要新的论证 |
| 缺少强制观察 | 保持未解决；不能变成通过或未经解释的豁免 |
| 提供的虚假事实 | 对其正确计算不能确立来源忠实性或现实世界中的真实性 |
| 适用的阳性用例 | 在声明的条件下能够成功；暴露永远拒绝的实现 |
| 保留前提的反驳案例 | 反驳指定的普遍结论 |
| 违反前提的案例 | 测试准入或范围；不得误标为对定理的反驳 |
| 判定基准的共享错误 | 报告一致性时说明共享依赖，不声称进行了独立验证 |
| 有限计数不符 | 协调公式、实际清单与观察计数；否则暂不提出覆盖主张 |
| 有歧义的保留观察 | 有限配置返回有效的冲突见证，而不返回确定评估 |
| 单元素 unknown 或不适用 | 保留模型的字面结果及其独立的应用证据义务 |
| 未达到观察 | 拒绝且不虚构结果 |
| 定义域扩展 | 新增的冲突状态使原纤维结果在扩展后的定义域上失效 |
| 相关与无关细化 | 将查询纤维中每一对冲突情形区分开的细化允许确定结果；仍保留冲突对的细化依然拒绝 |
| 变异后的诊断 | 压制预期区别的缺陷被未改变的预期答案发现 |
| 审查者或执行环境改变 | 记录实际分离程度及环境；不自动产生独立性或运行时迁移 |

这些是对所声称符合性范围的要求，并不是某个已部署实现执行了所有用例的报告。有限迁移检查器仅处理其选中的行。验证包真实性、来源忠实性、受控比较以及运行中消费者的绑定，需要各自的证据。

## 9. 审查、修订与兼容性 {#9-review-revisions-and-compatibility}

**SVR-R025.** 审查记录必须（MUST）标明确切对象字节、审查方法、审查者的访问权限及实质性共享依赖；必须（MUST）区分自我审查、同程序重跑、结构上另行组织的审查、独立复现和外部同行评审。

**SVR-R026.** 主张、准则、观察配置或实质性应用定义域发生变化时，必须（MUST）获得可标识的后继评估，同时保留先前记录及其实际支持的范围。

当其前提成立时，完整输入迁移论证可以证明保留未受影响结果是合理的。它不允许悄悄将旧审查重新标记为针对新字节。依赖图只能相对于已表示的依赖标识重新评估候选项；某个候选项受到影响，并不意味着其结论自动为假。

**SVR-R027.** 面向既有观察或交换配置的适配器必须（MUST）声明其字段与词汇映射、损失以及未解决义务；不得（MUST NOT）将本规范的发布表述为该适配器已经部署。

本草稿不改变现有状态标记、证据索引语义、历史报告或运行时协议。发布、源码集成、索引准入、部署和科学接受，分别保留各自记录。检查结果迁移之后，许可的当前使用条件仍然必不可少。

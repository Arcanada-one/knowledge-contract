# 知识契约术语表 {#knowledge-contract-glossary}

**出版版本：**1.1 · **维护者：**Pavel Valentov

本术语表规定科学论文、工程规范和工程研究共用的首选术语。面向读者的术语使用普通词语；接口要求使用代码标识符时，保留其字面拼写。俄语对应词用于追溯早期手稿，并不产生第二个实体。定义描述的是义务或观察；某一定义出现在本术语表中，并不构成某个具体实现满足该定义的证据。

## 知识及其表示 {#knowledge-and-its-representation}

| 首选术语（含英文对照） | 俄语对应词 | 定义与边界 |
| --- | --- | --- |
| 知识契约（Knowledge Contract） | Контракт знаний | 对知识、预期用途、依据、依赖、约束和评估义务的版本化规范。其存在既不确立真实性，也不授予执行权限。 |
| 语义对象（Semantic object） | Смысловой объект | 可寻址、具有版本的解释，包含内容、归属、上下文和依据。检索分块是用于搜索的一种表示，其边界不必与语义对象相同。 |
| 来源（Source） | Источник | 解释或观察所依据的材料。来源的作者身份、真实性、传达保真度和内容是否为真，是不同的问题。 |
| 来源表示（Source representation） | Представление источника | 文本、图像、表格、音频或其他材料的某个具体版本。 |
| 来源片段（Source fragment） | Фрагмент источника | 在指定来源表示中寻址的区域。其定位符必须说明适用的选取约定。 |
| 解释（Interpretation） | Интерпретация | 在明确假设下对材料的一种理解。多种理解可以同时保持为可能。 |
| 归属标注（Attribution） | Атрибуция | 可寻址内容与陈述、解释或评估该内容的人或系统之间的关联。 |
| 溯源（Provenance） | Происхождение | 记录形成过程中涉及的实体、活动和责任主体的轨迹。仅有可追溯性并不能证明正确性。 |
| 依据（Ground） | Основание | 在声明的假设下支持某项指定断言的来源、观察、规则或论证。 |
| 上下文（Context） | Контекст | 解释或使用内容所需的条件，包括指称对象、作用范围、表示、时间、例外、接收者及其他相关情境。 |
| 适用性（Applicability） | Применимость | 某个解释或制品在当前条件或明确指定的历史条件下，对某项具体用途的适合程度。 |
| 约束（Constraint） | Ограничение | 限制可接受的解释、变换、交付或行动的规则或条件。它是明确的契约义务，而不是验收标准的同义词。 |
| 受保护性质（Protected property） | Сохраняемое свойство | 变换被要求保留的指定观察或关系。 |
| 投影（Projection） | Проекция | 为特定目的选择的表示，明确列出纳入和省略的单元、变换规则以及损失。 |
| 损失（Loss） | Потеря | 在声明的观察模型中，变换未能保留的信息或区别。 |
| 不确定性字段（Uncertainty field） | Поле неопределённости | 对尚未确定的理解、限定或置信限制的明确记录。即使来源记录保留了该字段，在交付的投影中省略它也可能丢失信息。 |
| 已生成且未经审查（Generated and unreviewed） | Сгенерировано, не проверено | 两个不同事实：系统生成了内容，而符合要求的审查尚未得到证实。生成的描述不是作者的陈述；后续审查必须明确其对象和范围。历史代码可能以 `generated/unreviewed` 合并这两个标签。 |

## 要求、工作与行动主体 {#requirements-work-and-agency}

| 首选术语（含英文对照） | 俄语对应词 | 定义与边界 |
| --- | --- | --- |
| 工作项（Work Item） | Единица работы | 一个承载目标的单元，具有版本化的要求、约束、指派、尝试和验收标准。`WorkItem` 是同一概念的代码拼写，并非另一种类型。 |
| 要求（Requirement） | Требование | 请求的结果或过程在指定版本和范围内必须满足的条件。 |
| 验收标准（Acceptance criterion） | Критерий приёмки | 判断观察到的结果是否满足某项要求的规则。它必须绑定实际输出和执行尝试。 |
| 角色（Role） | Роль | 具名的职责和决策范围。角色定义与将角色指派给某个执行者是不同的。 |
| 技能（Skill） | Навык | 对方法或过程及其使用条件的可复用描述。`SKILL.md` 文件提供的是指令，而不是读者能够执行这些指令的证据。 |
| 胜任能力（Competency） | Компетенция | 在指定条件下实现某类结果的、被规定或被评估的能力。能力定义与有关具体执行者的证据仍是不同记录。 |
| 执行者能力（Capability） | Способность исполнителя | 已识别的执行者在实际环境中可用的能力；其确立程度取决于评估所能支持的程度。 |
| 方案蓝图（Blueprint） | Схема решения | 为实现结果而设计的可复用流程或结构安排，连接组件、步骤、依赖、选择、约束和验收义务。 |
| 指派（Assignment） | Назначение | 在指定范围内，将执行者绑定到职责或工作项。 |
| 权限依据（Authority） | Полномочие | 由已识别的授权依据提供的正当决策或行动范围。 |
| 具体授权（Grant） | Разрешение | 包含主体、行动、资源、目的、条件和有效范围的具体授权。 |
| 执行尝试（Attempt） | Попытка исполнения | 一次可寻址的执行尝试，绑定工作项、要求、契约、行动主体和输入。 |
| 结果状态（Outcome） | Исход | 操作在其声明的契约下产生的结果：成功、部分完成、拒绝、失败或未决，对应 `success`、`partial`、`refused`、`failed`、`unresolved`。 |
| 效果观察（Effect observation） | Наблюдение эффекта | 对一次尝试所造成的外部变化已经确立的事实。超时可能使其仍然未知。 |
| 就绪（Ready） | Готово к выдаче | 在指定配置下的可用性或生命周期就绪状态。它不是操作的结果状态，不能取代 `success`、`partial`、`refused`、`failed` 或 `unresolved`。已就绪的信息性结果不一定授予执行权限。 |
| 核心与配置（Core and profile） | Ядро и профиль | 核心提供共通义务；配置增加一组具名、版本化的表示或使用条件。配置不得取消核心的强制条件。 |
| 必需配置（Required profile） | Обязательный профиль | 为预期用途必须理解的配置，包括承载强制约束的任何配置。未知的必需配置会阻止该用途。 |
| 可选与不透明配置（Optional and opaque profile） | Необязательный и непрозрачный профиль | 只有在没有强制义务依赖某个可选配置时，才可保留该配置而不解释它。不透明表示其含义未被解释；保留字节并不意味着符合其语义。 |

## 检索、组合与复用 {#retrieval-composition-and-reuse}

| 首选术语（含英文对照） | 俄语对应词 | 定义与边界 |
| --- | --- | --- |
| 候选项（Candidate） | Кандидат | 检索得到、可能有用但仍等待特定用途所需检查的条目。 |
| 覆盖（Coverage） | Покрытие требований | 在指定阶段，对指定请求的必需槽位已经确立的支持。出现关键词不等于在语义上满足要求。 |
| 搜索保证（Search assurance） | Полнота процедуры поиска | 对搜索过程在其声明范围内的说明，与选定答案的覆盖程度相互独立。 |
| 强制依赖（Mandatory dependency） | Обязательная зависимость | 一种关系：特定用途要求另一个固定版本的单元或条件。 |
| 依赖闭包（Dependency closure） | Замыкание зависимостей | 在声明的图内，包含所选根节点及其全部有效强制依赖的最小集合。它不能恢复未记录的边。 |
| 上下文包（Context package） | Пакет контекста | 为特定用途选择并版本化的知识，包含要求、依据、依赖闭包、覆盖、投影和资源核算。 |
| 包与任务包（Package and task package） | Пакет и пакет задачи | 包是具有清单和身份的已声明集合。任务包还将选定内容绑定到请求及其义务。这两个名称都不意味着依赖闭包完整或体积很小。 |
| 文档档案（Document passport） | Паспорт документа | 历史包中的元数据记录，用来标识文档、表示、来源及相关条件。它不是身份证件，也不是独立的正确性证明。 |
| 操作闭包（Operational closure） | Операционное замыкание | 在指定操作中使用某个包所必需的依赖和绑定，例如角色、技能、规则、标准、来源引用和权限。只有图记录了每项相关义务时，图闭包才足够。 |
| 编译制品（Compiled artifact） | Скомпилированный артефакт | 从提取、选择、变换或组合中得到并保存的派生结果，附有生成配方和依赖。 |
| 构建配方（Build recipe） | Рецепт сборки | 生成制品时所用的声明输入、变换版本、参数及实质相关的环境条件。 |
| 内容身份（Content identity） | Идентичность содержимого | 在声明的表示和哈希域内的身份。当前交换配置 `sha256/raw-utf8-json-v1` 对精确的 UTF-8 JSON 字节进行哈希；它不承诺不同序列化形式的值具有相同身份。 |
| 查找身份（Lookup identity） | Ключ поиска кандидата | 从声明的候选项描述符导出的键。找到同一个键并不能确立描述符相等或使用资格成立。 |
| 候选项描述符（Candidate descriptor） | Описание кандидата для повторного использования | 实现在查找后比较的字段：对象和表示身份、生成配方和依赖、相关的请求范围与要求、时间模式、接收者以及权限范围。选定配置声明必需字段和比较规则；单独的标题或哈希不能替代这种比较。 |
| 准入（Admission） | Допуск к применению | 在已识别的政策和信任边界下，判定指定要求和约束允许某种具体用途的决定。 |
| 时效性（Freshness） | Актуальность по времени | 满足指定时间政策的性质，与语义适用性及授权相区别。 |
| 保留策略（Retention） | Срок хранения | 关于保存字节的存储政策，与这些字节可以有效使用多久相区别。 |
| 驻留状态（Residency） | Наличие в хранилище | 在某个存储位置观察到的、已识别字节的存在或不存在状态：`resident`、`evicted`、`absent` 或 `unknown`，分别表示驻留、已逐出、不存在或未知。它本身不说明时效性、真实性或获准用途。 |
| 制品生命周期（Artifact lifecycle） | Жизненный цикл артефакта | 准备、评估、使用、被新版本取代、撤销及存储的状态和事件。保留策略只是其中的存储部分，并非整个生命周期的同义词。 |
| 失效处理（Invalidation） | Пересмотр пригодности | 一种变化，要求撤销或重新考虑使用资格或派生状态。它不一定删除历史字节。 |
| 实际交付边界（Serve boundary） | Момент фактической выдачи | 选定结果实际释放给接收者时所采用的声明一致性点。 |
| 知识效用（Knowledge utility） | Полезность знания | 相对于规定基线和成本模型、取决于任务、政策和时间范围的收益。它不是文档固有的标量属性。 |

## 证据、版本与审查 {#evidence-versions-and-review}

| 首选术语（含英文对照） | 俄语对应词 | 定义与边界 |
| --- | --- | --- |
| 证据（Evidence） | Свидетельство | 在某种方法和信任边界下支持指定断言的可寻址观察或记录。仅声称测试通过，弱于可供检查的测试输出。 |
| 评估（Assessment） | Оценка | 受方法约束、针对具体对象修订版及其性质的判断。 |
| 评估结果（Assessment result） | Результат оценки | 对规定范围内某项性质的 `pass`、`fail`、`unknown` 或 `not_applicable`。只有具备已识别的规则和有依据的适用性见证，`not_applicable` 才能解除一项强制条件；它不能替代无法取得的证据。 |
| 可信输入（Trusted input） | Доверенный вход | 在声明的评估中作为前提接受的值。该值的结构一致性并不认证其外部来源或真实性。 |
| 信任边界（Trust boundary） | Граница доверия | 对某类证据或权限接受某个来源、主体或过程的边界。测试必须明确哪些输入由它检查，哪些输入被它预先假定。 |
| 反例（Counterexample） | Контрпример | 满足某项断言的相关前提但违反其结论的情形，或揭示遗漏了必要前提的情形。 |
| 符合性（Conformance） | Соответствие спецификации | 在声明范围内满足指定结构或行为要求。它并不确立对系统声称的所有经验性收益。 |
| 复现（Reproduction） | Воспроизведение | 在声明输入上再次运行可用过程，并按声明标准比较输出。检查保存的报告不是重新运行。 |
| 演示或示例（Demonstration or illustration） | Демонстрация или иллюстрация | 为展示机制或反例而构造的例子。重新运行它，复现的是该例自身的计算，而不是使用其他输入的历史实验。 |
| 独立重复（Replication） | Независимое повторение | 使用独立实现或观察、另行进行的断言评估。必须说明独立性，不能仅凭不同文件名或代理角色推断独立性。 |
| 程序合格性确认（Qualification） | Квалификация процедуры | 表明某个已识别实现满足声明的有限验收程序的证据。开发与回归控制可用于确认限定发行版的合格性；它们不确立在留出数据上的性能或一般能力。 |
| 预先登记（Preregistration） | Предварительная фиксация протокола | 在被评估的结果披露之前，记录预期输入、标准和分析。带本地时间戳的计划与公开登记的方案不同；二者都不能防止所有偏离或偏倚。 |
| 掩蔽条件审查（Masked review） | Рецензирование с замаскированными условиями | 使用对评估者隐藏条件分配的标签进行评估。文本仍可能泄露线索；掩蔽既不证明真正盲评，也不会自动使代理评估者具有独立性或经过校准。 |
| 阳性对照（Positive control） | Положительный контроль | 被设计为满足准入或成功条件的情形，用以避免始终拒绝的实现通过整个测试集。其代表性必须另行论证。 |
| 压力或边界用例（Stress or boundary case） | Нагрузочный пример или проверка границы | 有意构造的不利情形，用以探测模型或可信前提的边界。预期中的错误输入被接受，应作为边界失效报告，并与普通符合性计数分开。 |
| 回归控制（Regression control） | Регрессионная проверка | 在发生变化后重新运行已知用例，以检测所测缺陷是否复发。它不是未见挑战，也不是新的独立观察。 |
| 变异检查（Mutation check） | Мутационная проверка | 有意修改实现，并检查测试集能否区分修改后的行为。结论受到声明变异体及等价变异体的限制；检出几个变异体并不证明普遍正确性。 |
| 修订版（Revision） | Редакция объекта | 不可变且具有身份标识的内容状态。 |
| 出版版本（Edition） | Издание корпуса документов | 一组出版物及其阅读清单的协调版本。它独立于运行时协议或服务的版本。 |
| 表示配置（Representation profile） | Профиль представления | 对某类制品的编码和解释约定，具有版本。 |
| 当前选定修订版（Current head） | Текущая выбранная редакция | 在已识别的命名空间和政策内进行的可变选择。历史上的“当前”标记不能证明现在仍为当前。 |
| 采纳决定（Adoption decision） | Решение о принятии | 在权限主体的范围内接受某项规范或出版物的治理行为。它不是真值谓词。 |
| 内部代理审查（Internal agent review） | Внутренняя агентная рецензия | 由代理作出的记录化评估，注明实际输入、方法和限制。它不是独立的外部同行评审。 |
| 未知（Unknown） | Не установлено | 现有观察不能确立某个值或判断结果。没有正当规则，就不能将其替换为假、不存在或通过。 |
| 不予披露（Withheld） | Не раскрывается | 某个值因限制而不予披露。这并不声称该值不存在。 |

## 具有明确作用域的数学记号 {#scoped-mathematical-notation}

符号仅在各文档所指明的模型中有效。相同字母不代表相同量。下表用于防止将早期成本记号误认为科学效用模型中的记号。

| 符号 | 作用域与含义 | 文档之间的边界 |
| --- | --- | --- |
| \(R(q)\) | 语义对象与复用论文：请求 \(q\) 的强制条件 | 每项条件都需要通过的评估，或有依据的不适用性见证；不得默默排除未知条件 |
| \(\mathrm{Roots}\) | 依赖闭包模型：初始选定顶点 | 与 \(R(q)\) 及货币意义上的复用成本不同 |
| \(h\) | 知识效用论文：核算或决策时间范围 | 保存的复用研究曾用 `h` 表示命中比例；当前说明文本用 \(\rho\) 表示该比例 |
| \(V(k\mid\cdots)\), \(V_{\mathrm{set}}(S)\) | 效用论文与上下文组合论文：任务条件下的价值或集合价值 | 保存的复用程序中的 `V` 表示验证成本，在研究中现写作 \(c_v\) |
| \(N,G,B\) | 效用论文与复用研究：请求数、冷启动可准入路径成本、准备成本 | 仅在时间范围、质量要求和成本边界相同的情况下可比较 |
| \(c_{\mathrm{hit}}\) | 效用论文：获准命中的全部成本 | 仅在声明的全部命中简化情形下，且无额外重建、失效处理或存储成本时，等于研究中的 \(c_v+c_r\) |
| \(c_v,c_r,\rho\) | 复用研究：每次请求的验证成本、获准命中的额外成本、可用命中比例 | 历史数据与代码保留原有键 `V`、`R`、`h`；新计算必须说明映射 |
| \(F(N)\) | 复用研究：核算时间范围内的开销 | 只有当 \(F\) 及其他相关参数不依赖 \(N\) 时，固定成本的闭式盈亏平衡公式才适用 |
| \(\rho(x)\) | 约束变换论文：为重构而保留的残余信息 | 这是制品的函数，与复用研究中的标量命中比例无关 |

## 术语编辑规则 {#editorial-rules-for-terminology}

在英文正文中使用 **Work Item**，仅在字面标识符中使用 `WorkItem`。使用“技能”“胜任能力”“执行者能力”“角色”和“权限依据”时，必须遵守上述区别。“已验证”“已核实”“完整”“当前”和“独立”等词必须明确其对象与范围。只有在重复使用确实能明显减轻阅读负担时，才引入缩写。

引述的历史标签，例如“independent review”，在证据中保持不变。在本出版物讨论的研究中，这个标签通常指同一会话或同一代理家族中另行指派的代理，而不是独立的外部同行评审。当前摘要应明确这一实际范围。“精确”应指明所比较的字节或观察；“全部”应指明有限的计数总体。保存的开发、回归、压力和普通用例应保持分离，即使历史摘要曾将它们合并。

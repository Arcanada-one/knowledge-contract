# Состояния оценки, исполнения и публикации {#assessment-execution-and-publication-states}

**Автор:** Павел Валентов · **Издание публикации:** 1.1

## 1. Назначение и соответствие {#1-purpose-and-conformance}

Это набор архитектурных требований. Для совместимости необходим именованный профиль представления; реализованное подмножество обмена ограничено [наблюдениями, событиями изменений и объявлениями профилей](../status-model/SPECIFICATION.md#8-bounded-exchange-profile), а [профиль книжного пакета](../book-package/SPECIFICATION.md) имеет собственную схему. Наличие полного формата передачи контракта или развёрнутой среды исполнения не подразумевается.

Статус осмыслен только для названного предмета, свойства, редакции и области. Один флаг «проверено» не может достоверно представлять валидность схемы, верность передачи источника, истинность, покрытие, авторизацию, исход исполнения и публикационное рецензирование. Эта спецификация разделяет данные вопросы и определяет обязательства для переходов между состояниями.

Требования, набранные прописными буквами, используют [BCP 14](../../../../../reference/bibliography/BIBLIOGRAPHY.md#requirement-language).

**STA-R001.** Профиль ДОЛЖЕН (MUST) выбирать измерения, необходимые для его назначения, и объявлять любое правило агрегирования.

Не требуется прикреплять к каждой записи все возможные измерения. [Статья о свидетельствах](../../../../../papers/evidence-and-falsification/PAPER.md) объясняет, почему более сильные заключения требуют других свидетельств.

## 2. Запись наблюдения {#2-observation-record}

**STA-R002.** Каждое наблюдение ДОЛЖНО (MUST) указывать предмет и его неизменяемую редакцию, оцениваемое свойство, редакцию требований или критерия, метод, наблюдателя, существенное время, результат, основания и ограничения.

Результат без предмета не является переносимым свидетельством.

**STA-R003.** Если метод доверяет предоставленному входу, а не независимо удостоверяет его, эта предпосылка ДОЛЖНА (MUST) быть указана.

Словарь результатов проверки — `pass`, `fail`, `unknown` и `not_applicable`. Последнее значение требует продемонстрированного правила неприменимости, а не отсутствующих данных. Для конъюнктивного набора обязательных проверок любой применимый отрицательный результат препятствует приёмке; любой оставшийся применимый неизвестный результат препятствует заключению, что всё прошло проверку.

**STA-R004.** Положительный результат НЕ ДОЛЖЕН (MUST NOT) перезаписывать отрицательный или неразрешённый результат по другому обязательному свойству.

## 3. Канонические словари измерений {#3-canonical-dimension-vocabularies}

**STA-R005.** Профиль, использующий текущие значения, ДОЛЖЕН (MUST) использовать перечисленные ниже значения snake_case, не перегружая одно измерение смыслом другого.

**STA-R006.** Более старый профиль МОЖЕТ (MAY) сохранять свои исходные лексические значения только через явный адаптер, сообщающий о потерях.

| Измерение | Значения |
| --- | --- |
| Доступность информации | `known`, `unknown`, `not_applicable`, `withheld` |
| Покрытие | `supported`, `partial`, `unsupported`, `conflicted`, `unknown` |
| Полнота процедуры поиска | `candidate_only`, `exhaustive_in_scope`, `incomplete_procedure` |
| Локальная фаза исполнения | `planned`, `ready`, `running`, `paused`, `finished` |
| Исход операции | `success`, `partial`, `refused`, `failed`, `unresolved` |
| Причина остановки | `completed`, `clarification_needed`, `budget_insufficient`, `retrieval_limit`, `stale_evidence`, `precondition_not_met`, `cancelled`, `execution_error`, `reconciliation_pending` |
| Внешний эффект | `none_established`, `known_effect`, `unknown_effect` |
| Жизненный цикл артефакта | `building`, `ready`, `quarantined`, `retired`, `failed` |
| Наличие в хранилище | `resident`, `evicted`, `absent`, `unknown` |
| Актуальность по времени | `fresh`, `stale`, `expired`, `unknown` |
| Пригодность для повторного использования | `eligible`, `ineligible`, `unknown` |
| Влияние эволюции | `compatible`, `restricted`, `requires_review`, `blocked`, `unknown_impact` |
| Решение о повторном использовании | `exact_reuse`, `revalidate`, `rebuild`, `instantiate`, `refuse`, `unresolved`, `serve_stale` |
| Свидетельства по случаю | `planned`, `illustrated`, `executed`, `evaluated` |
| Вид рецензии | `editorial`, `internal_technical`, `independent_agent`, `external_peer` |

`unsupported` всегда относится к объявленной оценённой области. `ready` описывает доступность исполнения или артефакта и не является успешным исходом операции. `none_established` сообщает об отсутствии установленного эффекта в наблюдаемой области, а не утверждает отсутствие удалённого эффекта. Вид рецензии описывает фактический протокол, а не имя рецензента. Отдельно порученная агентная рецензия не является внешним научным рецензированием людьми.

**STA-R007.** Исторические метки ДОЛЖНЫ (MUST) отображаться явно: `terminated` → фаза исполнения `finished`; `unsupported in scope` → покрытие `unsupported`; «incomplete execution of planned search» → `incomplete_procedure`; `not_measured` → оценка `unknown` с причиной «no observation». Специфичные для профиля состояния качества, например `reviewed` книжного пакета, сохраняют собственную объявленную область; они не являются псевдонимами `pass`.

Влияние эволюции — вход решения о допуске, а не краткий путь к его заключению:

| Влияние | Пригодность и разрешённое следующее решение |
| --- | --- |
| `compatible` | Всё ещё `unknown`, пока не пройдены все остальные обязательные проверки; после этого пригодно для разрешённого политикой повторного использования |
| `restricted` | Исходный более широкий запрос непригоден; отдельно идентифицированный суженный запрос оценивается заново |
| `requires_review` / `unknown_impact` | Пригодность неизвестна; `revalidate` или `unresolved`, пока без допущенной выдачи |
| `blocked` | Непригодно для этого применения; `refuse` либо отдельная допустимая пересборка или экземпляр, оцениваемые по собственным основаниям |

## 4. Правила переходов {#4-transition-rules}

Переходы применяются к одной и той же идентифицированной попытке, экземпляру жизненного цикла, политике и области применения.

**STA-R008.** Реализации ДОЛЖНЫ (MUST) следовать таблицам; неуказанные переходы отклоняются.

Создание нового предмета или попытки начинает новую историю, а не меняет смысл старой записи.

**STA-R009.** Каждый переход ДОЛЖЕН (MUST) фиксировать вызвавшее его наблюдение, действующего субъекта, прежнее состояние и результат проверки условия перехода.

### Фаза исполнения {#execution-phase}

| Из | Событие и условие перехода | В | Терминальное? |
| --- | --- | --- | --- |
| попытка отсутствует | Выделить уникальную попытку с закреплёнными единицей работы и требованиями | `planned` | нет |
| `planned` | Установить входы, способность исполнителя и предусловия отправки | `ready` | нет |
| `ready` | Повторно проверить текущие полномочия и предусловия при фактической отправке | `running` | нет |
| `running` | Записать возобновляемую контрольную точку в рамках объявленной политики паузы | `paused` | нет |
| `paused` | Проверить контрольную точку, текущие привязки и обновлённые условия отправки | `running` | нет |
| `planned` / `ready` | Отменить, отказать или завершиться с ошибкой до отправки; записать причину и фактические наблюдения эффектов | `finished` | да |
| `running` / `paused` | Завершить с явными исходом, причиной и наблюдениями эффектов | `finished` | да |

**STA-R010.** Завершённая попытка НЕ ДОЛЖНА (MUST NOT) возвращаться к выполнению; повтор использует новую попытку с политикой повторов.

Последующая сверка добавляет наблюдения эффектов к той же исторической попытке, не изображая это как новое исполнение. Успешный код завершения процесса не восполняет недостающие свидетельства приёмки.

### Жизненный цикл артефакта {#artifact-lifecycle}

| Из | Событие и условие перехода | В | Терминальное? |
| --- | --- | --- | --- |
| жизненный цикл отсутствует | Выделить запись сборки | `building` | нет |
| `building` | Успешная сборка, обязательные проверки и атомарное условие публикации пройдены | `ready` | нет |
| `building` | Сборка неуспешна; сохранить причину и любой явно частичный выход | `failed` | да |
| `building` / `ready` | Уполномоченное расследование целостности, безопасности или происхождения приостанавливает применение | `quarantined` | нет |
| `quarantined` | Разрешённое снятие карантина после устранения причины, полной повторной оценки и проверки текущего условия публикации | `ready` | нет |
| `building` / `ready` / `quarantined` | Разрешённый отзыв или отмена выводят этот жизненный цикл из использования | `retired` | да |

`quarantined` означает приостановку использования на время расследования названной проблемы; снять её может только субъект, уполномоченный политикой. `retired` означает, что этот жизненный цикл отозван и больше не может стать готовым. `failed` также терминально для данной сборки. Замена или восстановление создают новую запись жизненного цикла или принятия и сохраняют прежние отзывы и ограничения. Идентичные байты не стирают эти решения.

### Проекции актуальности и пригодности {#freshness-and-eligibility-projections}

Это проекции неизменяемых наблюдений, а не редактирование прежних вердиктов.

**STA-R011.** Новые записи проекций МОГУТ (MAY) заменять текущее отображение только при сохранении наблюдений, на которых основывались прежние отображения.

| Измерение: из | Событие и необходимые свидетельства | В |
| --- | --- | --- |
| Актуальность: любое | Новая применимая проверка, действительные границы часов и текущая политика устанавливают новое окно | `fresh` |
| Актуальность: `fresh` | Мягкий срок достигнут, но ни один жёсткий срок не истёк | `stale` |
| Актуальность: `fresh` / `stale` | Достигнут жёсткий срок или допустимый предел возраста | `expired` |
| Актуальность: любое | Нельзя установить обязательные время, политику или хронологию | `unknown` |
| Пригодность: любое | Выполнены все текущие обязательные условия именно этого запроса | `eligible` |
| Пригодность: любое | Известное обязательное ограничение не выполнено | `ineligible` |
| Пригодность: любое | Существенная зависимость, полномочие или оценка становятся неизвестными | `unknown` |

**STA-R012.** Наблюдение с истёкшим сроком или непригодностью НЕ ДОЛЖНО (MUST NOT) перезаписываться лишь потому, что у другой записи более поздняя отметка времени.

Пригодность может стать положительной только после устранения каждой известной блокирующей причины в рамках текущей политики. Одна повторная проверка дайджеста не обновляет возраст события источника. [Политика повторного использования](../reuse-policy/SPECIFICATION.md) определяет семантику сроков и решений.

Наличие в хранилище меняется только по наблюдениям хранения: запись и обратное чтение названных байтов устанавливают `resident`; квитанция вытеснения — `evicted`; проверка отсутствия в указанной области — `absent`; отсутствие заслуживающего доверия наблюдения хранения даёт `unknown`.

**STA-R013.** Эти переходы НЕ ДОЛЖНЫ (MUST NOT) сами по себе менять истинность, рецензию, актуальность или пригодность.

Записи оценок, покрытия, полноты поиска, внешних эффектов, рецензий и свидетельств по случаям являются наблюдениями, допускающими только добавление. Для них нет автоматического движения к успеху: иллюстрация не становится исполненным испытанием без новой записи исполнения, а неизвестный эффект разрешается только свидетельствами с соответствующей границы эффекта. Конфликтующие наблюдения остаются адресуемыми. Монотонны история наблюдений, истории терминальных попыток и жизненных циклов, а также непереиспользуемые [поколения публикации](../cache-identity-and-invalidation/SPECIFICATION.md#5-guarded-publication-and-serving), а не постоянно улучшающиеся истинность или пригодность.

## 5. Научный и редакторский статус {#5-scientific-and-editorial-status}

Завершённая публикация может формулировать условные положения и сообщать об ограниченных результатах, признавая неотвеченные эмпирические вопросы. Номер её издания идентифицирует согласованный текст, а не доказательство всех будущих применений.

**STA-R014.** Словарь НЕ ДОЛЖЕН (MUST NOT) отождествлять «опубликовано», «рецензировано», «реализовано» и «эффективно».

**STA-R015.** Внутренняя агентная рецензия ДОЛЖНА (MUST) идентифицировать рецензента, входную редакцию, метод и заключения и ДОЛЖНА (MUST) быть помечена именно как внутренняя агентная рецензия.

Она не является независимым внешним научным рецензированием. Отчёт о конечных проверках требует фактических выходов; иллюстративный сценарий не является исполненной проверкой.

**STA-R016.** Исполненное неуспешное испытание остаётся полезным свидетельством и ДОЛЖНО (MUST) сохранять свой отрицательный результат.

## 6. Пользовательские проекции {#6-user-facing-projections}

**STA-R017.** Интерфейсы МОГУТ (MAY) суммировать эти измерения, но сводка ДОЛЖНА (MUST) сохранять различия, существенные для решения пользователя.

**STA-R018.** «Проиндексирована редакция X» точнее, чем безоговорочное «текущая». «Проверки предоставленной записи пройдены» НЕ ДОЛЖНО (MUST NOT) превращаться в «действие разрешено», если текущая авторизация была вне проверенной границы.

**STA-R019.** Неизвестный эффект после истечения времени ожидания ДОЛЖЕН (MUST) оставаться видимым, когда пользователь решает, повторять ли попытку.

Технические детали можно раскрывать по запросу, но критическую неопределённость нельзя скрывать за положительной отметкой.

## 7. Приёмка и свидетельства {#7-acceptance-and-evidence}

**STA-R020.** Проверки ДОЛЖНЫ (MUST) охватывать пройденную схему при ложных предоставленных основаниях, успешное исполнение с невыполненным критерием результата, завершённое выполнение с неизвестным эффектом, присутствующий в хранилище, но отозванный артефакт, корректный исторический результат, непригодный для текущей задачи, и внутреннюю рецензию, не устанавливающую эмпирическую валидность.

[Исследование соответствия](../../../../../engineering/studies/contract-profile-conformance/STUDY.md) демонстрирует важность предпосылки доверенного входа. [Редакторский пилот](../../../../../engineering/studies/editorial-skill-pilot/STUDY.md) сообщает о равной наблюдаемой оценке для структурированного и базового условий. Ни один результат не допускает общей метки эффективности. Различие между наблюдением и принятием правила см. в статье о [пересмотре и управлении](../../../papers/revision-and-governance/PAPER.md).

## 8. Ограниченный профиль обмена {#8-bounded-exchange-profile}

[JSON Schema](../../../../../schemas/contract-observation.schema.json), [валидатор](../../../../../tools/check_contract_profile.py), [примеры](../../../../../schemas/fixtures/contract-observation/valid) и [тесты](../../../../../tools/test_contract_profile.py) определяют конкретное подмножество обмена: `kc-observation/1`, `kc-dependency-change/1` и `kc-profile-advertisement/1`. Это оригинальный профиль проекта, использующий [JSON](https://www.rfc-editor.org/rfc/rfc8259) и [JSON Schema 2020-12](https://json-schema.org/draft/2020-12/json-schema-core), а не заявление о совместимости полного Контракта знаний, исполнителя или API.

**STA-R021.** Обменная запись ДОЛЖНА (MUST) быть одним строгим JSON-объектом в UTF-8 без BOM, повторяющихся имён членов на любой глубине, токенов неконечных чисел или изолированных суррогатов Unicode.

Неизвестные поля, профили и версии записей отклоняются.

**STA-R022.** Целые числа, используемые как эпохи или порядковые номера, ДОЛЖНЫ (MUST) находиться в диапазоне от 0 до 9,007,199,254,740,991.

Строки отметок времени используют секунды UTC `YYYY-MM-DDTHH:MM:SSZ` с корректной календарной датой; другие модели часов требуют иного профиля.

| Запись | Обязательные поля и смысл |
| --- | --- |
| `KCObservation/v1` | `observation_id`, `subject`, оцениваемое `property`, закреплённый `criterion`, `id`/`version` метода, `observer`, `observed_at`, `result` проверки, текстовый `scope`, `evidence_refs`, `trust_assumptions`, `limitations` |
| Ссылка на предмет, критерий или свидетельство | `artifact_id`, неизменяемая `revision`, `hash_domain`, точный `sha256` |
| Наблюдение `not_applicable` | Дополнительно закреплённое `inapplicability_rule`; его присутствие — только структурное свидетельство, а не доказательство применимости правила |
| `KCDependencyChange/v1` | `event_id`, упорядочивающее `namespace`, `sequence`, `dependency_id`, прежние и новые эпохи и редакции, `kind` события, влияние, наблюдатель и время; см. спецификацию кеша |
